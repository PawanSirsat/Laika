**Decisions**
- The Overview's journey is derived from `GET /agents/devices` only. Until
  pairing exists, a device is its agents' shared label (SPEC §4.67), so
  *device added* = an active agent exists, *tool added* = an active agent has
  been seen. *Returning* (no funnel, *Set up a project* primary) = any active
  agent seen. Revoked agents count for nothing (§H). Status words are
  *Active / Idle / Offline / Not connected yet* from `last_seen_at`; *Ready*
  is not used because there is no verification evidence yet (§E.3).
- `?add=device` and `?add=tool` both open the existing registration wizard,
  which asks device and harness together; `?tool=` preselects the harness.
  D4 replaces this with the real wizards. The alias for
  `?tab=connect&agent=X` therefore goes straight to `add=tool&tool=X`
  (the plan's "no device → add=device first" needs D4's wizards).
- `projects` and `activity` render the classic content in every mode except
  that `v3` puts an access note above Projects (plan §C: V3 versions only in
  v3). Activity is unchanged, including its "Once per machine" chip.
- Advanced re-hosts Tokens with *New token* in its own card (plan §B.1
  "Move into Advanced"), not the page header.
- Disabled overflow items stay skipped by the arrows (the existing test
  asserts that); they are now `aria-disabled` and programmatically focusable.
