**Decisions**
- **Reading, not writing.** CHIEF asked for hooks into the existing paths, so no
  writer changed. Everything comes from `activity` and `member_notices`.
- **A time watermark, not `rowid`.** VACUUM may renumber the rowids of a table with
  a text key, so the stream's cursor is wrong for a persisted one. Idempotent keys
  make the overlap re-read free.
- **When to mail on `task.created`.** Only if no later row changed the assignee:
  neither a `task.assigned`, nor a claim's `task.status_changed` carrying
  `assignee_id`. A task created unassigned and then claimed was mailing its
  claimant; a test caught it.
- **While off.**
  - Instant mail is still written, as `email_off`: the audit LAI-1312 promised.
  - No digest collects, so turning email on floods nobody.
- **The digest.**
  - It goes after 07:00 local (`user_time_settings.place`, UTC when unset), once
    opened before that morning.
  - It's worded on the server, because no server-side wording existed.
- **Preferences.**
  - Defaults are both on.
  - Session only, as `notices.own` is: whether a person hears from Laika is theirs to
    decide.
- **The profile card** sits below the Overview rows, in its own `.prof-email`, so the
  rows' shared-height checks never count it. It draws nothing if either read fails.
