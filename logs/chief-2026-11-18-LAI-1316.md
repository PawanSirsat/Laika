**Decisions**
- Hand-added a `DROP TRIGGER IF EXISTS time_entry_revisions_is_append_only_no_delete`
  before the rebuild. Without it the generated migration fails at the
  `RENAME`, which is SQLite refusing a trigger on another table that names
  the dropped `time_entries` (measured, error below). I chose this over
  `PRAGMA legacy_alter_table`, which changes what a rename rewrites;
  `ensureActivityTriggers` already recreates the trigger on every boot.
- I added out-of-office (`showAs: oof`) to the skips the task listed, since
  it is not working time. An organiser whose `responseStatus` is `none` is
  logged, because Graph answers that for some meetings a person organised.
  Both are written into D-157 item 3.
- A title rule never reads a private meeting's subject. Otherwise a keyword
  rule would put a private meeting in a space, which shows what its subject
  is about even though the title says *Busy*.
- Calendar entries never reach the Solidtime outbox, because the outbox
  already allows only `draft` and `manual`; a new test proves it. They are
  editable like manual ones (`currentFields` refuses `import` only).
- A meeting that runs past the person's local midnight is clipped to
  midnight rather than refused, so the entry stays on its own day.
- The mapped space is not checked against the member's spaces. This follows
  the Solidtime import, which maps a Solidtime project to a space the same
  way. An owner or admin wrote the rule, and the time is the member's own.
- Test connection always asks for a fresh token and puts it in the sync's
  cache, so a grant made since is picked up by the next tick rather than
  after the old token lapses. A Graph 401/403 also drops the cached token.
- `calendar.sync` is placed before `hr.sync`: `scheduler.test.ts` holds HR
  last, as the last `atStart` job, and this job is not `atStart`.
- Rule `project` in `CalendarRuleView` is an inline one-line type, because
  the web drift guard reads a multi-line inline object's fields as the
  parent's.

**Discovered**
- `error in trigger time_entry_revisions_is_append_only_no_delete: no such
  table: main.time_entries`. This was the first rebuild of `time_entries`,
  and any later one needs the same line, so it is written into the
  migrations README.
- The rebuild puts `time_entries`' columns in schema order. 0047 and 0057
  had appended five at the end. No query reads by position; the migration
  test compares the columns by name and the rows by key.
- The channel rule matches the meeting's `location.displayName`, which
  Teams sets to the channel for a channel meeting. This is unverified
  against a live tenant, because consent is still pending. So is reading
  `/users/{email}`: Graph resolves a user by UPN or id, so a member whose
  Laika email is not their UPN reads as `no_mailbox`. Both need a live check
  once `Calendars.Read` is granted — left for CHIEF to file, not filed here,
  so that several builders taking ids from the same range at once do not
  collide.
