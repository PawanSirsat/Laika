**Decisions**
- **A rehype step plus a context, not a plugin built from the people list.**
  The step needs no data, so it stays a module constant. That is the rule
  `task-markdown-props.test.ts` guards. A plugin built per render would have
  been an open-ended transform again.
- **Each text node is matched on its own, in both the reader and the
  editor.** Formatting markup then sits where the server sees a non-address
  character, so `**@grace**` and `x **@grace**` agree with
  `parseMentionHandles`. Matching the joined paragraph text would have made
  `foo**@grace**` a mention on the server and plain text on screen.
- **A machine pill has no fill**: an outline and secondary ink. A grey fill
  (`--bg-column`, like `.marker-system`) stands further from a white surface
  than a person's lilac tint. "Softer" would then hold only by chroma, not
  by contrast.
- **One people list for the picker and the pills.** Filling in the Owner
  reader's handle from `/me` also makes their own picker entry insert
  `@handle`, which the server resolves, instead of `@Full Name`. Keeping two
  lists would have been more code to keep a worse insertion.
- **The untouched-description browser guard asserts no pills.** The pills
  are in a test of their own, so the guard passes before and after, as the
  criterion says.

**Discovered**
- **A mention mark with no writer can be invisible to the byte-for-byte
  guard.** If its text keeps the `@`, it writes every byte back and the
  round trip stays green, although marks are in the parsed document. A
  property test now covers that case: a mention parses as plain text. The
  task file records the run.
- In dark, `--chip-purple*` equals `--accent*`. A mutant on those tokens
  trips the pairwise check before the ordering check. That is the trap the
  task file names, and it is now measured.
- **Three server tests timed out under load** during the root gate, in
  files this change does not touch. They passed when re-run alone. Already
  the territory of LAI-715 and its kind: nothing filed.
