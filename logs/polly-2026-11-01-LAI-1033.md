**Decisions**
- **Matched by `created_at`, only past the newest journal `when`.** That is
  the migrator's own key. A rollback's journal is a prefix of the newer one,
  so every unknown row is past its end. Refusing middle rows would gamble a
  deploy outage on a case nobody has seen.
- **The restore triggers on "this run wrote a snapshot", not on the refusal.**
  Both lose the same data, and that data is kept aside either way. This trigger
  also covers an old image without the guard, which is the first rollback after
  this ships, and saves the 90-second refusal.
- **The marker carries the run id.** Without it, a deploy that failed before
  reaching the instance would leave the last good deploy's marker. The
  rollback would then restore the snapshot taken after that deploy, losing
  everything since. A test and a mutation pin this.
- **The oldest snapshot since the marker, not the newest.** A crash-looped boot
  re-snapshots a half-migrated file.
