**Decisions**
- Pre-paint theming by a classic external script in `<head>` — the only way
  to run before first paint with `script-src 'self'` and no inline script.
  The rule is duplicated in plain JS, so the boot test runs the real file
  against `resolveTheme`/`readFont` over every combination rather than trusting
  the copy.
- Previews scope theme tokens with `[data-theme-preview]` added to each theme
  block's selector list, `:root…` last — rather than a second set of preview
  colours, which the single-source rule forbids and which would drift.
- System's dark variant is its own stored key, absent when Dark, like
  `system` itself, so a future default reaches people who never chose.
- One-click switches go dark/black → light and light → the reader's variant,
  so a Black reader toggling twice lands back on Black.
- No in-app motion/transparency override: the app honours the OS settings
  through tokens; an override would mean duplicating each media block under a
  class. The section says what the OS currently asks for and where to change it.
- Density omitted: there is no density mechanism in the app.
- The reduced-transparency browser check reads the CSSOM rather than emulating
  the media feature — headless Chromium ignored CDP's
  `prefers-reduced-transparency` (measured: `--glass-2` stayed translucent).
