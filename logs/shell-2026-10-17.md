**Decisions.**

- **The primary guard is structural.** The prompt path runs as installed
  with fork() refused (`ulimit -u 1`, then `exec`). zsh abandons a script
  whose fork fails and exits 1, so any fork fails the run: git, curl, a
  command by absolute path, `$(…)`, a subshell. A fork before the write
  leaves no line; one after it gives exit 1. The fork-free way to a socket
  in zsh is a module (`zsh/net/tcp`, `zsh/net/socket`). So a second run
  sources the hook into a zsh whose EXIT trap lists its modules, and only
  `zsh/datetime` and `zsh/system` may be added. Each test first proves its
  instrument works: a script running `/usr/bin/true` must fail (as root the
  limit is ignored), and a loaded `zsh/net/tcp` must show in the list.
- **Wall time is kept, against the right yardstick.** At load ~20 the hook
  inflated about 2.5×, a bare `exit 0` about 1.7×. The fastest-of-41 ratio
  read 2.1 to 3.2 and the median ratio up to 6.7. That is why "≤ 2× bare"
  failed. Each hook run is now paired with a floor script that does the
  same drain, clock, read and append, in alternating order. The claim is
  ≤ 5 ms fastest, or a median pair ≤ 2× the floor. Quiet: 1.01–1.06×. In
  three root gates at load ~20: 0.93×, 0.85×, 1.06×.
- **Not isolated with `--test-concurrency=1`.** `pnpm -r` runs server and web
  alongside `cli` anyway, and the floor pairing made isolation unnecessary.

**Mutations**, inserted beside the prompt path's `printf` (anchor checked,
hook restored by checksum in a trap): `/usr/bin/true`, `git rev-parse`,
`curl 127.0.0.1:9`, `zmodload zsh/net/tcp && ztcp`, a `$(…)` after the
write, and a 20 000-step builtin loop. All six went red and the unmutated
hook stayed green. The `/usr/bin/true` mutant ran 4.69 ms fastest and the
`$(…)` one 3.58 ms, both under the old 5 ms budget. **The old timing test
could not see either one.** Only the fork-refused test catches them.
