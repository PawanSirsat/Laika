**Decisions**
- **The bearer token is stored only as its hash.** It is compared, never sent anywhere, so
  nothing needs to read it back. Hashing gives the fixed-length compare CHIEF asked for at no
  extra cost.
- **The believed Authentication-Results.** A sender can write any such header, so only the
  named receiving server's headers count, else the topmost. Without this, DMARC would be
  decoration: a forger writes `dmarc=pass` themselves. `email_inbound.auth` records the
  verdict words even for `switch_off`, so an owner can read the server's name from a test mail
  before turning it on.
- **`/webhooks/*` resolves no credential.** Brevo's bearer collided with Laika's token auth,
  and every delivery was refused before the route ran. §10's first sentence already says
  "no user session". This is flagged to CHIEF as outside the plan.
- **`created_via: 'webhook'`** (decision a). There is no rebuild of `tasks`, `comments` or
  `activity`.

**Discovered**
- `authserv_id: ''` was validated before it was mapped to none. The service test caught it;
  it is fixed.
