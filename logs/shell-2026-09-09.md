
## LAI-441 → review. The password echo now has a guard.

**Changed**
- `cli/test/prompt-raw-mode.test.ts` (new). **No production change** — LAI-422's
  fix is correct; this is the guard it never had.
- Filed **LAI-232**: the Board's sprint branch has never been rendered in a test.

**Decisions**
- *`node-pty` permitted, not taken.* The mechanism assertion fails on exactly the
  edit that caused the bug — shown, not assumed — and a native module in a
  package whose pitch is `npx` with nothing installed is a real cost for one test.
- *One scenario, not three.* See below.

**Discovered**

**My first assertion failed against correct code.** I asserted **0** readline
listeners at raw-mode entry, from a probe on a bare `PassThrough` where
`close()` does leave 0. It leaves **1** in the real harness. So I measured both
sides through the actual code before rewriting it:

```
           while open   at askSecret's setRawMode(true)
close()    2            1     <- let go
pause()    2            2     <- did not
```

The assertion is now *"fewer than while open"*. **The number was never the
property** — "the readline let go before raw mode was set" is.

**Substituting `process.stdin` works once per process.** The first `prompt.ts`
instance sees the fake; a second does not, however the module is cache-busted,
and `askSecret` then never settles. Measured outside `node:test` too, so it is
the substitution and not the runner. **Stated in the file rather than worked
around**, and the single scenario runs in the order `init` actually uses.

**The mutation column that matters:** all three edits are red for the new guard
and **green for the pre-existing suite** — which is precisely the gap LAI-441 was
filed on.

## LAI-452 → review. A failed spawn was posing as a hook exit code.

**Changed**
- `cli/test/plugin-hooks.test.ts` — `runHook` distinguishes *"never ran"* from
  *"exited N"*; the 20s `execFile` timeout removed. **No change to the hook.**

**Decisions**
- *Retry only a transient failure to start, immediately and bounded.* Not a sleep
  and not more time: a machine that cannot fork is not a fact about the hook.
  `ENOENT` is not retried — a genuinely missing hook must stay loud.
- *The 20s timeout is gone rather than raised.* Raising it is the longer fuse
  AC3 forbids; the hook is 109–125ms under 20 spinners, so the bound never
  protected anything this suite could reach.

**Discovered**

**The task named the wrong test, and that is the finding.** Reproduced 1 in ~13
under load — and it was `the token stays out of argv`, not *"unconfigured is
silent"*. Both start with `assert.equal(run.code, 0)`, and **whichever test is
running when the machine cannot fork is the one that loses.**

`execFile` reports a failure to *start* through the same callback as a non-zero
exit, with `error.code` a **string** errno; the harness mapped anything
non-numeric to `1`. So a spawn failure arrived as `code: 1`, stdout `''`, stderr
`''` — **byte for byte what a hook exiting 1 silently looks like.** Proved by
spawning a nonexistent path rather than waiting to catch it in the wild.

**The `node_modules missing` warning was a red herring** — the task offered it as
a lead. `cli/node_modules` does not exist because pnpm hoists to the root, so it
prints on every run in this package.

**And my first soak was wrong in the same shape as the bug.** It reported 3
failures in 50 using `grep -q "^# fail 0"`, which cannot tell an assertion
failure from a run that never produced a summary, and captured no detail. The
re-run separates them, captures every failure, and verifies the load was present:
**0 and 0 in 50, with 24 spinners alive and load ~127.** A soak whose failure
detection conflates two outcomes is this task's own defect one level up.

**Ports:** none. The owner's local instance is still up on 3371.

## LAI-464 → review. The spawn-failure fix now has a guard.

**Changed**
- `cli/test/plugin-hooks.test.ts` — `spawnOnce` extracted as a seam; the thrown
  message carries the attempt count; three assertions added.

**Decisions**
- *A real absent path, never a stubbed errno.* Handing the mapping a fake
  `error.code` tests it against a fixture of itself; the point is that the
  **operating system** produces this shape, and asking it costs nothing.
- *The attempt count lives in the message.* It is what makes "ENOENT is not
  retried" assertable — otherwise adding it to the transient set is invisible.
- *`code` is asserted not to be `1`, by name.* `1` is a real exit status a hook
  could return; that collision is the whole bug.

**Discovered**

**A mutation of mine came back green and the mutation was the thing that was
wrong.** It replaced the message's trailing sentence while the assertion reads
`the machine, not the hook`, earlier in the string. Re-aimed at the text the
assertion actually reads, it is red.

**That is the fourth place this repo has hit the same shape today** — a harness
whose anchor missed, a fixture pinned to a calendar, a soak conflating two
outcomes, and now a mutation aimed at the wrong words. **A green from an
instrument you have not verified is not evidence**, and the mutation is supposed
to *be* the verification.

**The row that justifies the task:** restoring the exact pre-LAI-452 one-liner
left the suite at **72 passing, 0 failing** before this, and turns this guard red
now.

**Ports:** none.
