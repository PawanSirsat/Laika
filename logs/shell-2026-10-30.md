**Decisions**
- "Delivered to" is not built. No REST endpoint returns §4.69's deliveries;
  §5.1 forbids stubbing it or adding it from a UI task. It was raised on the
  card for CHIEF to file, because CHIEF's LAI-500 – LAI-599 block is full and
  no task file could be numbered.
- An agent is named only when it is the reader's own (`GET /agents` answers
  nobody else's); another person's agent reads "through an agent".
- "Save mine over rN" is an explicit overwrite after a confirmation, not a
  merge: merging is out of scope ("editing semantics beyond optimistic
  write").

- No client/server drift pairs for the three new types. CORE's
  `server/test/tooling/response-type-coverage.test.ts` lists them as
  UNPAIRED, so pairing them from `server/web/` reddens a CORE guard (CI run
  40946671397); that is §4.4's `clientOmits` shape the other way round. The
  pairs and the UNPAIRED removal belong in one change, for CORE to land with
  the deliveries endpoint.
- The Compare pickers are the app's `Dropdown` and Copy is `CopyButton`: a
  native `<select>` and a direct `navigator.clipboard` both fail repo guards
  (LAI-726; the one clipboard implementation).

**Discovered**
- At 390 px the context panel was 422 px wide and started 18 to 51 px off the
  screen, and that was true before this task: the padding sat outside
  `width: 100vw`, and `.projects > :not(.screen-page)` gave the fixed panel
  an 18 px side margin. Both fixed here; the browser test now asserts the
  panel's box against the viewport, and goes red with the gutter rule put back.
- The first 390 px assertion (the panel's own `scrollWidth`) could not see
  that: a box that is itself too wide reports no overflow.
