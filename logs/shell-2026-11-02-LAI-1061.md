**Decisions**
- The pairing code lives in component memory only. A reload resumes by
  `?pairing=<id>` and says the code is not shown again.

  the board's answer, and *Paired* only on `completed`.
- No `features.*` gate: the manifest still says `false` for pairing and
  exchange though both are served; the CLI's business to check.

  wizard says is Connected, because Ready is defined by recency (§H).
- The browser-secret "Set up by hand" fallback was not built: the task said
  no secret anywhere. An unpaired device's tool row keeps the classic
  rotate, as before.
