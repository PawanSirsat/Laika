**Decisions**
- **Radius absorbs to the nearest rung, as `visual-language.md` §4.4 lays
  out** (1–2→hairline, 3–4→chip, 6–7→sm, 8–11→card, 14→column, 16–20→sheet,
  a 20px chip→pill). The alternative — a token per value in use — would have
  kept 37 rungs and been no scale at all. Cost: corners change by 1–2px; the
  screenshot diff shows only corners (largest: a 56px space avatar 14→12px).
- **Spacing moved exact matches only, and completed the scale with half
  steps** rather than snapping 6/10/14px onto 4/8/12/16. The census found
  6px 432 times, 10px 251, 14px 155: snapping would have moved nearly every
  screen, which the task forbade. Half steps keep the 4px rhythm readable
  (`-1-5` sits between `-1` and `-2`) and are one scale, not a second.
- **What spacing could not move is a ratchet, not a pile of reasons**: the
  exemption list is every remaining declaration, file by file, compared as a
  multiset, plus one reason per off-scale value (hairline / odd pixel / rem
  fraction / between steps / em). A new literal anywhere fails, and so does an
  exemption whose declaration has gone. The 485 are LAI-1179.
- **Breakpoint names keep the doc's** (`phone` 600, `tablet` 900, `laptop`
  1180, `desktop` 1280, `wide` 1440, `ultra` 1600) and add the validation
  widths the task asked for (390, 768, 1024) plus 480 and 640, which the
  screens already used 18 and 23 times. Collapsed only where behaviour is
  identical: `30rem`/`480px`, `37.5rem`/`600px`, `40rem`/`640px`,
  `64rem`/`1024px`, `80rem`/`1280px`. The 13 widths that differ (379, 544,
  560, 720, 736, 760, 848, 896, 960, 1000, 1040, 1100, 1200) are listed with
  what reflows and how far the nearest name is; moving them is visible.
- **`N-1px` max and `N+1px` min are allowed forms**, not offences: 1279/1280
  and 899/901 are exact complements of the named widths, and "normalising"
  1279 to 1280 would change the layout at exactly 1280, a validation width.
- **px, not rem, in `@media`**: a `rem` there follows the browser's default
  font size, not the root's, so `40rem` equals `640px` only at the default.
  Converting changes behaviour only for a reader with a non-default browser
  font size; one unit is what lets the guard compare.
- **Container queries are out of scope**: they measure an element, not the
  viewport, and stay in `rem`.
