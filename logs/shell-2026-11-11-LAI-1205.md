**Decisions**
- ConfirmDialog keeps its own shell on the shared contract rather than being
  re-rendered through Dialog — its mark/words layout and its phone geometry
  are pinned by several browser tests; the behaviour is what had to be one.
- Exit is instant: the parent unmounts, which also hands focus back without
  a wait. Holding the overlay mounted for an exit animation would delay every
  caller's state and every test that waits for `detached`.
- The box a Dropdown can be portaled into (Dialog, SidePanel) only fades; its
  rows carry the rise. A transform on the box, even mid-entrance, makes it the
  containing block of the fixed-position list (LAI-726's bug). The confirm
  has no list inside and keeps rise + scale on its card.
- Layer numbers kept as they were (10…90) and named, not renumbered — only
  migrated files read the tokens, so nothing unmigrated moves. A guard that
  every z-index ≥ 10 is a token is a follow-up, not done here.
- No glass, no theme.css edit, no new dependency, no Radix.
- B16 was already fixed on this base (Dropdown 70 > panel 61, portaled into
  the nearest aria-modal); this adds the tokens and a browser test.
- Skills (advice; repo rules won): **emil-design-eng / animate** — applied:
  transitions not keyframes, strong ease-out `cubic-bezier(0.23,1,0.32,1)`,
  140/200/240ms, never from `scale(0)`, menu origin at its trigger, modal
  centred, no animation on a keyboard-opened menu, reduced motion = none (the
  task asked for none rather than the skill's gentler fade). Rejected: exit
  animations faster than entrances — exits are instant, see above.
  **apple-design** — applied: dim-to-focus scrim for modals, sheet from the
  bottom edge on a phone, panel from its own edge, enter along the path it
  sits on. Rejected: translucent materials (PR #291 owns glass) and springs /
  gesture dismissal (no gesture here, no motion library under the CSP).
  **impeccable (polish)** — the launcher binary was absent
  (`scripts/impeccable` not on disk), so its references were read directly;
  applied: fix at the narrowest level (one primitive, not 30 patches), check
  both themes at real sizes — the 1440 screenshot caught Cancel floating mid
  footer from a stale `margin-left: auto`, fixed.
  **review-animations** — its checklist used via emil-design-eng's table.

**Discovered**
- `task/FeedComment.tsx` pre-spent Escape (`preventDefault` on a window
  capture listener) so the drawer would not close with its delete
  confirmation. Under the contract the confirmation spends its own Escape,
  and the pre-spent key read to it as "a control inside already used this",
  so Escape stopped closing it — `task-feed.test.ts` caught it in shard 3.
  The workaround is removed (`6153b2e3`). Swept every capture-phase keydown
  listener in `server/web/src` (untruncated grep): `HandoffOfferDialog` and
  `AddToProjectDialog` close their own dialog on capture and stop the event;
  they host no confirmation or Dropdown, so they do not conflict — follow-up:
  move both onto Dialog.
- `test/browser/overlays.test.ts` first leaked its harness when setup failed,
  which kept the test process alive for 30 minutes — found by mutating the CSP
  check; `board()` now closes on a failed setup.
- The harness serves no CSP (the design-system proposal's "would pass CI"
  gap); `overlays.test.ts` serves one for its pages. A harness-wide option is
  a follow-up.
- Follow-ups above are listed, not filed: the id range for polly-dispatched
  tasks is polly's to allocate (LAI-1208 runs in parallel).
