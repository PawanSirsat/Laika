- **Does stopping `omni polly -p` stop the server-side work? Not by signal.**
  - SIGTERM: the client exits 143, but the session stays `running` and a 30 s
    `UserPromptSubmit` hook runs to the end.
  - SIGINT: the client waits for the turn to end, then exits 0.
  - `POST /v1/sessions/{id}/events {"type":"stop_session","data":{}}` returns
    202. The session is `idle` within 3 s, the hook is cut off, and
    `SessionEnd` fires.
- **Does the hook path fire inside polly? Yes.**
  - polly's `claude-sdk` brain spawns `claude_agent_sdk/_bundled/claude` with
    user settings loaded.
  - `SessionStart`, `UserPromptSubmit` and `SessionEnd` ran, with `OMNIGENT=1`
    and `CLAUDE_CODE_ENTRYPOINT=sdk-py`.
  - `Stop` was not observed: with no Claude login no turn completed. The
    failing turn said `Not logged in`, which is why a hook held the turns open.

**Decisions**

- **The Omnigent run's identity switch (D-118) came along with the marker.**
  - The brief listed the bridge, the marker and session-reopen. But the spike
    showed polly's own turns open sessions through Claude Code's hooks, and
    polly's MCP is the bridge, which acts as the Omnigent agent.
  - With hooks still opening sessions as Claude Code's agent, the
    `session_id` polly is told could not be claimed with: it belongs to
    another agent.
  - So hooks, the Claude helper and the Codex helper all switch together, and
    only when `omnigent.json` exists on the device. This is
    `agent-hook.sh`/`polly-home`/`mcp-headers.sh` ported; F8 lists them.
- **The copy is named `laika-polly`**, so `omni agent add` never shadows the
  built-in `polly`. `omni polly` always runs the bundled copy (cli.py
  14046-14086), so B must start `omni run <laikaPollyDir> -p`. That is in
  the PR.
- **The Codex helper is a `sed` one-liner, like Claude's**, not
  `node … mcp-headers`. Codex runs it in a shell, measured. It needs no Node
  path that could move, and it reads Codex's own `OMNIGENT=1` through
  `$PPID`.
- **`agent-omnigent.ts` lives here**, though the plan listed it under B, as
  the brief asked. The PR says so, so B imports it.
- **The restart line is printed as asked.** `omni agent --help` says an added
  agent needs no restart; the line is harmless, and it also drops any polly
  session started before.

**Discovered**

- **Omnigent 0.19.1 has no `OMNIGENT=1` literal.**
  - The research agent's grep found none, but this worker's own `claude`
    process carries it.
  - Its source is `runner/identity.py`'s `OMNIGENT_SESSION_ENV_VAR =
    "OMNIGENT"`. Grep for the constant, not the assignment.
- **On macOS `ps -E` shows no environment for platform binaries**
  (`/bin/sh`, `/bin/sleep`), and does for `claude`, `codex` and Homebrew
  `node`. Tests that need a readable parent use a Node process.
- **Any test of the hook path run on Belka sees an "Omnigent run"**: every
  process descends from an Omnigent-launched `claude`. The local runs went
  through a runner reparented to launchd with `OMNIGENT` unset, like CI. The
  script is in this session's scratchpad: a double fork, then
  `env -u OMNIGENT…`.
- **`omni stop` / `server stop` also sweep and kill any healthy Omnigent on
  :6767** (`stop_untracked_local_server`). Never run them from a throwaway
  HOME on Belka.
- **`endSession` writes `ended` before it sends the end**, so a test has to
  wait for the request, not the state.
- **Belka still runs LAI-589's wrapper.** The new code is compatible with it:
  under `polly-home` there is no `omnigent.json`, and the wrapper decides
  plain or Omnigent first. Retiring the wrapper is an owner step and not part
  of this task.
