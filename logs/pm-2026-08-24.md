**Decisions**
- **`ready` is derived, never stored** (SPEC §4.5) — `backlog` + unassigned + all
  dependencies `done`. A stored flag needs recomputing on every dependency
  transition and will eventually be wrong; a derived one cannot drift. Costs a
  join on `list_ready_tasks`, which is cheap at our scale.
- **`discovered-from` is provenance, not a dependency.** Kept as a column on
  `tasks`, separate from `task_dependencies`, so a discovered task can be worked
  before its parent closes. Conflating the two would make every discovery block
  itself.
- **Claiming is compare-and-swap at the API level** (SPEC §5) and `git mv` at the
  file level — deliberately the same idea twice, so the protocol builders follow
  by hand matches the one the product enforces. Second claimant gets `409` with
  the current assignee, not a silent overwrite.
- **Root config files are not in any builder's area.** Rather than granting
  Builder-A the repo root, LAI-001 lists the eight root files it may create, and
  `CLAUDE.md` §1 states that scope exceptions must name files individually.
  "Whatever else is needed" grants nothing.
- **`can()` is pure and synchronous**, with the caller loading the actor and
  resource. Keeps it exhaustively unit-testable against the §3.1 matrix, which is
  the only way that table stays true.
- **LAI-012 (plugin skeleton) seeded now despite being M4 work.** It has no
  dependencies, and without it Builder-B has only LAI-008 during M1 — which
  itself waits on LAI-001/LAI-002. This is the difference between Builder-B
  working and Builder-B waiting.
- **Task ids renumbered against the roadmap** so M1 is a contiguous LAI-001..009
  and M2 starts at LAI-010; the out-of-milestone plugin task took the last id
  rather than sitting in the middle of the M2 range.

  The numeric prefix is what GitHub maps to the account, so attribution is exact
  and no personal address ends up in a public log.

  beats a permanently misattributed root commit in a personal repo.
