**Decisions**
- Read the body first and re-wrap it in a `Request`, rather than passing
  `parsedBody`. Passing `parsedBody` would have meant our `JSON.parse` running
  before the SDK's `Accept` and `Content-Type` checks, which turns a 415 into a
  `-32700`. Re-wrapping keeps every SDK answer exactly as it was, and parses
  only once.
- The `reason` comes from where `JSON.parse` stopped, never from its message.
  V8's message quotes the input, and "at position N" with N at the end of the
  text is the shape of a cut body. The SDK's own messages are logged only when
  they match its fixed sentences. Anything else (its catch-all at :697 can
  carry an arbitrary error) is logged by name, so no body text can reach a log
  line.
- No proxy or bridge change: none of them miscounts. Writing a Traefik change
  for CHIEF would be a fix with no defect behind it.

**Discovered**
- `-32700 Parse error: Invalid JSON` from this SDK doesn't mean the JSON was
  invalid; it means `req.json()` rejected for any reason. With this change, the
  `reason` and the two lengths in `mcp.transport_error` say which. Nothing
  filed.
- The AWS box's container is stopped but the instance still runs
  (i-0b2fa45c15e1b10cf). That's CHIEF's call under the AWS freeze, so nothing
  was filed.
