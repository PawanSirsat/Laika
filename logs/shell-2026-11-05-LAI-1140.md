**Decisions**
- A cold Timeline does not walk the space to open one task (D-074): an id is
  one `GET /tasks/:id`; the shared set is used only when already held or when
  the link gave a key — rejected subscribing always, which the Timeline test
  now refuses.
- On `/board` and `/list` the host waits for the view's offer rather than
  reading the set itself in the moment before it lands — a second walk for
  nothing.
- Meeting review opens the drawer over the review itself, not on the board —
  the reader came to judge a proposal and closing should leave them there.
- The panel split (spec S1) went only as far as the host needed: the seam is
  `TaskSource`; `useTaskWorkroom` and the area components remain for S1.

**Discovered**
- B1 had a second cause the audit did not name: Timeline, Sprints and Dashboard
  hold their own `useRoute()`, and `pushState` tells no one, so the shell never
  saw their `?task=` — fixed here in `use-route.ts`.
- `?new=task` had no reader anywhere: Create from any view, the board included,
  landed on the board with no form — fixed here by B19.
- Views without a store of their own pass no `executionSignal`, so a drawer
  opened there does not quietly re-read activity on a live claim frame; it
  re-reads on the next open. Left for S1 (`useTaskWorkroom`), not filed.
