**Decisions**
- **The CLI signs in to the board, with the person's password, for each run,
  and keeps no session** — not a token. §3.1 serves a person's confirmed hours
  to no token, not even its own person's, and pushing them means reading them;
  a token exception would reverse that sentence and is a decision, not a build
  choice. Cost: no unattended schedule. Benefit: an agent with the machine's
  token can neither read the hours nor write them anywhere.
- **Laika edits after a push go out only while Solidtime is unchanged** — the
  orchestrator's brief said edits and deletes in Laika update Solidtime; the
  task file said Laika never overwrites Solidtime once pushed. Both hold: the
  CLI compares Solidtime's digest before writing and leaves any Solidtime
  change alone; the pull then takes it (a conflict, Laika's kept in the
  revisions). Project and description are changed only when Laika's card or
  space moved (`moved`), so the person's words in Solidtime survive a minutes
  edit.
- **The link is on the board, not only in the CLI's sent-log** — a manager's
  `pull --all` has no other developer's sent-log, and without the board's
  `solidtime_entries` it would import every pushed entry again as a duplicate.
- **The description never leaves the machine**: the board gets the key the
  CLI read from it (leading key, else the only key; a Solidtime task name's
  key first) and a SHA-256 of start, end, project, task and key. A reworded
  description is therefore not an edit.
- **`closed_through` is a column now, written by nothing yet** — the import
  and outbox honour it today, LAI-789's month close sets it. A setter here
  without LAI-789's lock on Laika's own edits would be a close that does not
  close.
- **Deletes are inferred only for members a batch says it covers, and only
  from a complete window**, so an employee's key, a failed page or a batch of
  some members cannot delete anyone else's hours.
- Timeless entries go to Solidtime at 09:00 local, after the day's earlier
  timeless entries (`offset_minutes`), so a day's typed entries never overlap
  each other.
