## 13:05 — [ops] Struck a criterion that described a defect that does not exist

**What changed**

- `.tasks/in-progress/LAI-224-forbidden-stream-reads-as-unreachable.md` — copied
  to `master` from the `shell` branch, `assignee` corrected to `shell`, and a
  review note appended striking criterion 2.

**What happened.** CORE, newly reassigned, probed a real Chromium against
Laika's exact `403` response shape before touching anything, and found LAI-224's
premise half wrong. `EventSource` on a `403` makes **one** request and stops —
`readyState` is `CLOSED (2)` inside `onerror`. Connection-refused and
mid-flight-death report `CONNECTING (0)` and do retry. Criterion 2 asked SHELL to
stop a retry loop that was never running, and to find it in a server log where it
does not appear.

**Decisions**

- **Struck the criterion rather than rewording it.** What it was reaching for is
  already criterion 1's: a banner promising a reconnection that will never be
  attempted *is* rendering an unreachable instance. Rewording would have been
  adding a criterion in the shape of a correction, and §2 exists to stop exactly
  that. The task got smaller, not larger.
- **Left the Goal's original wording intact** and put the correction in the note.
  The Goal is the record of what was believed on 2026-08-25; overwriting it would
  make the file claim the bug was always understood correctly.
- **Recorded CORE's argument against the Notes' preferred fix without deciding
  it.** `use-shell-context.ts` subscribes independently, so passing the board's
  known `403` down to the stream leaves the banner alive on every screen where
  the board is not mounted. That is a strong argument and I think it is right —
  but the implementation choice belongs to whoever builds it, and a note that
  quietly settles it is a design change to someone else's work.
- **Required SHELL to reproduce the measurement rather than build against CORE's
  table**, and told them that if their run disagrees, my note is what is wrong.
  CORE asked for this standard themselves.

**Discovered**

- **My "~720 commits behind" was wrong; CORE was 28 behind.** `git branch -v`
  printed `[ahead 720]` against the stale `origin/builder-a` and I read the
  direction backwards. I had already unset those upstreams an hour earlier for
  exactly this reason and then quoted the number they produced anyway. Corrected
  to both sessions. A stale remote does not just clutter — it produces numbers
  that look like measurements.
- **The self-expiring-exemption list is six, not four.** I had LAI-052, LAI-080,
  LAI-043, LAI-213; CORE added LAI-066 and LAI-211 from their own time as SHELL.
  Six occurrences is a stronger pattern than four, and it changes which half of
  LAI-409 is load-bearing: the **derived** pair list matters more than the
  exemption entry. An exemption that self-expires protects the case someone
  thought about; enumerating registered tools and failing on any without a twin
  or an exemption protects the case nobody did.
- **A reassigned session read its new task cold and found a defect in a
  *different* session's task before starting its own.** Worth noting as a reason
  the reassignment was worth doing beyond filling an empty seat.
