**Decisions**

- **Renamed only what is live.** `.tasks/done/`, `logs/` and existing DECISIONS
  entries keep the names they were authored with. They are the record, and the
  append-only rule that governs decisions governs them too — rewriting them
  would make the history claim things happened differently than they did. The
  mapping lives in `CLAUDE.md` and `.sessions/README.md` so an old name is
  always resolvable.
- **Did not touch `server/`, `server/web/`, `plugin/`, `cli/`, `docker/`.**
  Those files name sessions in comments and READMEs and are now stale, but they
  are the builders' files. Filed LAI-400 and LAI-401 instead. A rename is not a
  licence to edit someone else's area — if I crossed here I would have no
  standing to send a builder back for doing the same.
- **Moved the worktree directories rather than leaving `Laika-builder-a/` on
  branch `core`.** A half-rename is worse than either state: the directory name
  is the first thing a session sees and it would have contradicted the branch.
  `git worktree move` preserved CORE's uncommitted LAI-045 work — verified after
  the move, five files still modified.
- **Left `origin/builder-a` and `origin/builder-b` alone.** Deleting remote
  branches is outward-facing and the owner's call. Both are stale snapshots —
  local `core` is 720 commits ahead of one, `shell` 747 ahead of the other — and
  builders never push, so they are harmless. Unset the upstreams so neither
  branch reports itself as diverged from a name that no longer exists.

**Discovered**

  issued. Found while trying to file the two follow-up tasks. This is exactly
  the failure D-017 was written to prevent: with no free number in your own
  block, the only options are reach outside it or collide. D-036 gives each
  session a second block.
- **D-017 had already reserved `LAI-300`–`LAI-399` for a fourth session.** My

  `LAI-400`. D-017's own revisit trigger was "a session exhausts its range", so
  D-036 is the revisit it asked for, answered the way it said it would be:
  another range, not a renumber.
- **BSD `sed` does not support `\b`.** The first rename pass silently left every
  `PM` untouched while reporting 24 changed lines in `CLAUDE.md`, which looked
  like success. Only grepping for what should have gone caught it. `[[:<:]]` and
  `[[:>:]]` are the BSD equivalents. Same lesson as the browser probes: when a
  check says the work is done, first prove the check can see the thing it claims
  to have removed.
- A bare `s/pm/chief/g` would have turned `pnpm` into `pnchief` throughout the
  repo. Guarded against it with an explicit grep before applying — worth keeping
  as a habit for any repo-wide substitution of a short token.
