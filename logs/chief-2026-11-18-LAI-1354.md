**Decisions**
- **Session only in the service, not in §3.2.** `task.delete`'s cell is also cancel's, and
  LAI-1356 has yet to decide whether cancel moves to it. Making the policy action session-only
  would decide that for it.
- **A task in Trash does not exist to a token**, for `GET /tasks/:id` (every MCP tool) and every
  write. Comment and attachment *lists* by id still answer a token. I recorded that in SPEC
  rather than claiming every read.

  reason; the subtask instant, the work ending and the request re-ask are shared, and LAI-1353's
  tests passed unchanged through the refactor.
- **The days left are computed on the client** from `TRASH_DAYS = 30`, because nothing scrubs
  yet. LAI-1355 makes the server enforce it.

## 2026-11-19T00:20:00Z — LAI-1354, review round (independent reviewer)

Two findings, both real, both in the token rule. Fixed:
1. **A token could still read a task in Trash's comments, files and rounds by id**, and the
   other `/tasks/:id/*` routes. I had recorded that as a limit; the reviewer rightly called it a
   break of the contract the PR states.
   - `server/src/http/middleware/trash-gate.ts` (new, mounted in `app.ts` on `/tasks/:id` and
     `/tasks/:id/*`, after auth) calls `assertTaskReachable` (`services/task-archive.ts`).
   - A token now gets the missing-id `404` under the whole subtree, read or written.
   - Its mirror test asks ten routes and a write, then shows a person, a live task and
     `/tasks/summary` untouched.
2. **A trashed parent answered a token `409 deleted`, not `404`.** `assertParentAllowed` never
   got the caller; it does now, from both call sites.

**Found while fixing (1):** `get_task_context` read a task's blockers with `getTask`, unguarded.
So once Trash 404'd to tokens, a *live* task with a blocker in Trash failed whole for an agent.
It now reports that blocker `{ id, visible: false }`, as it already did for a parent the token
cannot see. There is a new MCP case for it.

SPEC §6.4 now says the subtree, the parent and the blocker. Each fix's mutant went red on its
test: the gate unmounted, the parent's caller dropped, the blocker catch removed.
