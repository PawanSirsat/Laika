**Decisions**
- **The migration is 0074, not the plan's 0072** — 0072 and 0073 shipped after
  the plan's base. §4.82 was taken too, so presence is §4.83 and pings §4.84.
- **Every refusal to ping is the agent `404`**, including the caller's own
  agent when it is revoked, ungranted or read-only. The plan says *"everyone
  else gets 404"*; a `422` with a reason for one's own agent would have been
  kinder and is a second shape to keep identical. Eligibility is asked
  **before** any rate bucket is spent, so an outsider cannot drain the
  per-agent 30 (asserted).
- **`201` for a new ping, `200` for the repeat** — the plan's §4 says `200
  {ping}`, its mutation list says `201`. Both hold this way, and `created`
  says which. The body is `{ ping, created }`.
- **The pinged agent id goes in the payload as `agent_id`**, already one of
  `AGENT_ID_KEYS`, so the project feed withholds it from anyone who may not
  see that agent with no new key to register. The row's own `agent_id` stays
  the writer's — the pinging agent — because `recordAgentEvent` never
  delivers to the writer, and putting the target there would deliver nothing.
- **The answer schema is two unions** — `launcher` on/off and `battery`
  known/unknown — so `percent` cannot accompany `unsupported` and `off`
  carries no run counts. `harness_ready` is three booleans rather than one.
- **Presence follows §4.2**: with presence off, `reported_at` and
  `started_at` are null and an enabled report reads `unknown`, as a client
  report and a project setup already behave. D-126 does not say; a launcher's
  freshness is "when was this laptop awake", which is what the switch hides.
- **Retention is pruned on write**, not by a §11.6 job: rows older than seven
  days go in the next ping's transaction. A job needs a §3.4 system action
  and `jobs/`, outside the plan's file list. An idle org keeps its last
  week's rows until its next ping.
- **The envelope version is bumped to 2** because the code's own rule says a
  change to the detail bumps it. No client reads `schema_version` today.
- **`task_key` and `project_slug` are frozen into the detail at write time**,
  not joined when served. The join was tried first: after `ANALYZE` the
  planner scanned the tiny `projects` table, and the bounded-plan guard in
  `test/services/agent-events.test.ts` refused it; a lookup only when rows
  exist changed the plan set with the data, which the same guard refuses.
  Frozen is also what the envelope already promises (*"what was true when it
  was written"*), and an old key still resolves through the prefix history.
- **The route test is `test/http/routes/capacity-pings.test.ts`**, not the
  plan's `agent-capacity.test.ts`: `structure.test.ts` wants a same-named test
  for `http/routes/capacity-pings.ts`, and a rename beat an exemption for a
  module that is tested.
- **`project-repo-setups.test.ts` now migrates through 0073 only.** It
  asserts what 0073 alone touches, and 0074 rebuilds `activity`; that rebuild
  has its own test, which seeds agent events and deliveries — the rows the
  rebuild's cascade could take — and checks every row, rowid and object.
