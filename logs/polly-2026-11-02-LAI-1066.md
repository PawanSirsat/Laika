**Decisions**
- A repository is `repo_key` (SHA-256 of the normalised remote, or of `label:<label>` with none) plus a chosen label — never a path; the server refuses anything that is not 64 hex, and an `instructions_path` with a leading `/`, `~`, `..` or a backslash.
- The agent comes from the token: a local-check body carrying `agent_id` is `422`. A personal token is `403 not_an_agent` — it is neither the tool that read the file nor the owner signed in.
- An agent asking about a project outside its grants gets the existing `403 agent_not_granted` from `requireReadableProjectBySlug`, the same as every agent read, rather than a new 404 — and an unknown slug answers the identical body.
- `project_match` / `prefix_match` are worked out by the server from the block's slug and prefix at record time, not trusted from the CLI. Stored flags, so a later prefix change is not reflected until the next check (noted, not built).
- Upsert by select-then-write in one transaction rather than a unique index: `agent_id` is nullable and a SQLite unique index treats NULLs as distinct.
- No `created_at`: with presence off `checked_at` is null and a timestamp column would say when someone worked anyway.
- CLI exit codes follow `laika doctor`: 0 current, 1 needs action, 2 could not record, 64 usage; no credential or `--offline` prints only and is not a 2.
