**Decisions**
- **Verb is `task.agent_selected`, not the proposal's `agent_selected`.** Every verb is dotted, and an append-only name is permanent. One verb covers set, change and clear, as `task.assigned` does.
- **Selecting is `task.write`.** No new §3.1 action: the selection is a field of the task, like size.
- **Eligibility.** Only your own agent, active, with a `full` grant, in a space whose agents are allowed. A `read_only` grant is refused separately, because that agent couldn't do the work.
- **Refusals** are 422 `unprocessable` with `details.reason`, in the `not_on_project` shape. §6.3's codes are closed.
- **Storage is `handoff_offers` in the §4.4 shape**, so LAI-546 can add columns without migrating rows. Withdrawing a request sets it to `cancelled`. Re-selecting the same agent is a no-op.
- **`activity.agent_id` is set inside `appendActivity`**, read from the token row, not passed by callers. No call site can forget it or name a different agent.
- **`/agents/me/work-requests` is agent-token only.** A session or legacy token gets 403 `not_an_agent`. It is filtered in SQL to projects the agent can read now, so pages are never short.
- **`activity.agent_id` uses restrict, not set null.** A set-null cascade would be an UPDATE, and the append-only trigger refuses UPDATEs (LAI-135).
