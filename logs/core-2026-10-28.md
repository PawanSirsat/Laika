## 2026-10-28T01:40:00+02:00 — LAI-539

**What changed**
- server/src/auth/tokens.ts — `findTokenById`: re-reads a token by primary key and re-applies revocation/expiry through `lapsed`, now shared with `findTokenBySecret`
- server/src/auth/resolve-actor.ts — `reloadActor(db, previous, now)`: person and token re-read together; returns the `TokenRejection` reason on failure
- server/src/http/routes/events.ts — open streams use `reloadActor` instead of `loadActor` (which dropped `token`, the M10 leak); token streams re-check before each batch is filtered, before it is written, and on each keepalive; failure sends one `error` frame with the 401 `unauthorized` body and closes; every event held to the token's current pin (`insidePin`); injectable `now`
- server/test/http/routes/events.test.ts — 7 tests in `open token streams re-check credentials (LAI-539)` (kept from the Codex worker's uncommitted draft; sound as written)

**Decisions**
- The write-time re-check runs once per batch (first frame), not per frame — per-frame would be a token and user lookup for every event; the gap left is microseconds between filter and write, covered by the per-frame `insidePin` against the latest actor.
- No cache "invalidated by revoke": a PK lookup per batch is cheap and has no invalidation path to get wrong. The existing code already did a `loadActor` per batch.
- `insidePin` is checked explicitly beside `visibleTo`, so the whitelist does not depend on every `can()` action narrowing by token. Mutation: removing the filter-time `insidePin` stays green because the write-time check and `can()` still hold — redundant by design, so recorded rather than tested twice.
- Cookie streams keep closing silently; only token streams get the `error` frame.
- "Agent revoked": this base has no agent-identity schema, so the token holder's deactivation stands in (test `closes a deactivated token agent stream with unauthorized`).
