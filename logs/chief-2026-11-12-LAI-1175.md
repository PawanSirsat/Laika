**Decisions**
- `ledPeople` does not seed the reader (the plan said "plus the reader"). A
  space admin holds `time.days.read_project` only through a membership row,
  so they are among the led spaces' members already; the seed was dead code
  and a mutation dropping it survived. Removed rather than keep a claim no
  test proves; the doc comment says why the reader is there.
- `users` is read for every candidate before the A–Z cut, not after: the
  names decide the order. Only places and working days are read for the
  shown ids. The plan's "three batch reads after the slice" is two.
- `TimeLoggingUser` is a named type on both sides. `view-type-drift`'s
  `fieldsOf` read the client's multi-line inline `user` object's fields as
  the row's and reported four fields the server "does not send";
  `TimeReportPerson` solved the same thing the same way.
- The everyone scope reads `time_entries_day_idx` / `time_drafts_day_idx`,
  not `_user_day_idx` as the plan said: with no `user_id` in the WHERE a
  `(user_id, day)` index cannot be ranged. The lead scope uses `_user_day_idx`.
  The index test holds both, by name.
- The browser test's state fixture is October 2026 with the server's own
  `today_day` inside it. The client takes today from the server's facts, so
  the pinned clock only decides which month opens and whether › is disabled;
  a fixture relative to the real today would put "before joining" in the
  previous month on the 1st–3rd.
- A month stepper arrow at the current month is a `<span aria-disabled>`,
  not a disabled link — a link cannot be disabled and the address is the
  state.
