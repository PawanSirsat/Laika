**Decisions**
- **Split the SPEC row rather than qualify it.** One row maps to both
  `token.list_any` and `token.revoke_any` in `policy-spec-drift`; a `(not for
  the owner)` on that row would have been verified against listing too, which
  stays unrestricted.
- **Strict below the owner, not for the owner.** The `agent.revoke_any`
  shape, so an unloaded target is never read as "not the owner". The owner's
  own cell stays a plain `✓` (true with no target), which keeps the drift
  guard's plain-cell comparison meaningful. Unlike `agent.revoke_any`, the
  caller's own token is allowed: an admin revoking their own token through
  the admin path was already a tested `204`.
- **Guard before the idempotent return**, so an admin is refused the owner's
  token whatever its state (tested).
- Code stays `forbidden` with `details.reason: not_for_owner`, the shape
  `developer-setup.ts` already answers with.
