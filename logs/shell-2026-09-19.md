**Decisions**

- **The §5 transition table splits by principal, and the seam is `actor.token`.**
  The obvious predicate, `isSystemPrincipal`, is *wrong*: it means
  `kind === 'system'` — cron and webhooks — so a token-bearing agent is an
  ordinary `ResolvedActor` and branching on it would have handed every MCP
  caller the widened rule. Checked rather than assumed.
- **The composite FK is `CASCADE`, not `RESTRICT`.** RESTRICT is the obvious
  choice and it is unsafe here: SQLite resolves cascades in **table-creation
  order**, and drizzle-kit emits tables alphabetically, so
  `board_column_statuses` is created first and a project delete then fails.
  Measured both orders both ways. RESTRICT's correctness would have rested on
  how two tables happen to be *named*.
- **The backfill gives existing projects five lanes, not the new four.**
  `DEFAULT_COLUMNS` folds `backlog` into "To do", which is the better default and
  would be a silent edit to a live board on upgrade.
- **`todo` leads "To do", not `backlog`.** The first status is the primary — what
  a drop sets and where the lane's colour comes from — and there is no
  `.lane-dot-backlog` rule, so the enum's order would have drawn a grey lane
  labelled "To do" that dropped cards into `backlog`.
- **A 404 from `/board-columns` falls back to one lane per status.** Rejected an
  error screen: a 404 is a server without the feature, and those five labels were
  already ours. It also keeps all 14 existing board fixtures green.
- **The View settings trigger lives in the space bar, not the slot below it.**
  First built in the slot; `sprint-strip.test.ts` caught that this adds a band
  the reference does not have. Moved rather than weakening the guard.
- **Group-by ships read-only.** A drop there is three endpoints with three
  permission checks and no keyboard equivalent. → LAI-288.
- **Seeds live in `db/`, not `services/`.** eslint caught `db/backfill.ts`
  importing `services/` — CONVENTIONS §2 makes `db/` the bottom layer.

## 2026-09-19T12:44:30Z — LAI-290

**What changed**
- server/web/src/routes/screens/BoardScreen.tsx — `onWheel` on `.board-main`
  forwards `deltaX` to whichever element is the horizontal scroller at the
  current width
- server/web/src/routes/screens/board/board-rail.css — `.board-main` gains an
  explicit `overflow-y: hidden`
- server/web/src/routes/screens/board/board.css — `.lane-body` gains
  `overflow-x: hidden`; the `+` tile is a 2rem square, `align-self: start`
- server/web/test/browser/board-lane-scroll.test.ts — `CROWDED_STUB` and three
  tests: sideways-over-a-card, vertical-over-a-card, no vertical scrollbar

**Decisions**
- **The wheel handler asks which element scrolls rather than assuming
  `event.currentTarget`.** Above 1200px `.board-main` is the scroller; below it
  goes `overflow-x: visible` and `.kanban` scrolls itself instead
  (`board-rail.css`'s `max-width: 1200px` block). Binding to `currentTarget` —
  which is what I wrote first — is a no-op at exactly the widths the owner was
  most likely to hit. The alternative, moving the handler onto `.kanban`, loses
  the wide case for the same reason.
- **`overflow-y: hidden` is declared rather than left to default.** `overflow-x:
  auto` coerces a `visible` `overflow-y` to `auto`, so the pane became a
  vertical scroller nobody asked for. It then scrolled over a 91px phantom — the
  clipped `.lane-move` / `.lane-order` absolutes, positioned against it — while
  every real child ended 18px inside. That is why the bar had no visible content
  under it.
- **CSS cannot fix the sideways case, so the fix is JS.** Measured both
  candidates: `overflow-x: hidden` leaves `.lane-body` a scroll container and
  Chrome still latches to it; `clip` is coerced back to `hidden` because the
  other axis is `auto`.

**Discovered**
- **Chrome latches a wheel gesture to the first scroll container under the
  pointer and drops the axis that container cannot scroll** — it does not chain
  to the ancestor that can. Measured: the same gesture over lane padding gave
  `scrollLeft=90`, over a card `scrollLeft=0`.
- **React's `onWheel` is passive, so `preventDefault()` in it is inert.** Found
  while mutation-checking: mutating the handler to `preventDefault()` left the
  vertical test green. The test does go red on the version that can do the
  damage — a native `addEventListener('wheel', …, { passive: false })`. Both
  facts are now in the test's comment, because the first one alone would have
  read as the test being weak.
- **A guard clause aimed at `.lane-body` measured the wrong lane.**
  `CROWDED_STUB` puts every card in `todo`, which is column *one*, not zero, so
  `querySelector('.lane-body')` returned an empty lane with no overflow and the
  test failed on its own guard. Same family as the fixtures that could not
  violate the property they checked — three times this week now.
- nothing filed; all three are properties of code I own.

**State**
LAI-290 still in progress — the toolbar duplicates the inline Priority/Tag/
Assignee selects in the space bar, which is the last item before review.

## 2026-09-19T12:55:00Z — LAI-290 (shared gate)

**What changed**
- `/tmp/laika-gate/gate-lock.sh` — a lock both sessions take around the gate.
  Outside the repo deliberately; nothing in the tree changed.

**Decisions**
- **A file lock, not "message me before you commit."** The other session asked
  for the message version. `pnpm test` is ~4 minutes and we are both async, so
  the window in which a message can cross a gate run is the whole run — the
  protocol fails exactly when it is needed. A lock does not depend on timing.
- **`mkdir` as the primitive, not `[ -f ]` then `touch`.** `mkdir` is atomic and
  fails when the directory exists; check-then-create has a race as wide as the
  check, which is the bug the lock exists to prevent.
- **It breaks a lock older than 15 minutes.** A gate that can be wedged for ever
  by a crashed run would get bypassed by hand within a day, and a protocol
  people route around is worse than none.
- **Kept out of the repo.** It was in `.laika-local/` first and `git status`
  went `?? .laika-local/` — `.gitignore:9` is `*.db`, which covers the database
  and not the directory. An untracked file in a checkout two sessions share is
  what a stray `git add -A` sweeps. Moving it out beat editing `.gitignore`,
  which is repo-root config and CHIEF's; no task needed once it lives in `/tmp`.

**Discovered**
- **A stale *snapshot* and a stale *browser cache* look identical until you use
  `curl`** — the other session's find, worth keeping: `curl` returned a bundle
  hash with **no matching file** in `public/assets`. A browser cache cannot
  produce that, so the one line separates "hard-reload" from "you are looking at
  a different build root". It is the same family as the `200`-from-the-SPA-
  fallback trap logged above: the measurement succeeding for the wrong reason.
- nothing filed.
