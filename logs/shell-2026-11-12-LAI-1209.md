**Decisions**
- Tooltips got their own layer above dialogs — the #318 tooltip sat at 70 and
  #332's Dialog at 80, so once both land every tooltip inside a Dialog would
  draw under it. Caught by the "drawn under the dialog" assertion (mutation
  M11 below).
- The tooltip spends Escape (`preventDefault` + `stopPropagation` on `window`
  capture) rather than leaving it to pass as #318 did — the owner's brief asks
  Escape to close the tooltip and not the dialog. `window` capture is the only
  place that runs before the `document`-capture Escape listeners several
  dialogs register at mount.
- Toolbar overflow by **container query on the toolbar**, not a window media
  query or a ResizeObserver: the same editor sits in the dialog, the panel and
  a comment at different widths in one window, and CSS cannot flicker or run
  late. One tool list feeds both bar and menu, so nothing can be in both or
  neither.
- The Agent line under the picker stays visible; only the Agent-vs-Assignee
  difference went into a hint — it is the consequence of the choice, not
  secondary help.
- Raw-button dialogs (column, Send back) keep their buttons and get a
  visible reason linked by `aria-describedby`, instead of being restructured
  onto `Button`; the brief said not to restructure.
- Follow-ups listed in the task file rather than filed: CHIEF's id block is in
  use by polly's own dispatches right now (LAI-1193…1209), and a guessed id
  would race it.
