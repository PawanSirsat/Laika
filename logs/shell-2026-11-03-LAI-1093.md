**Decisions**
- The old CLI's way forward is a fresh install beside it, not a pull of the
  old checkout: the page cannot know where the old one is or what state it
  is in, and a pull fails on both cases that hit today (elsewhere; detached).
- Two install blocks (no ~/laika yet / ~/laika exists), each an `&&` list
  over three lines, rather than *run this instead of the first line*: a
  pasted block whose clone is refused must not go on to link whatever is in
  the folder. The scanner allows `&&` only as a word of its own; Add device's
  existing fresh bootstrap already used it.
- The classic Connect flow's `clone || pull --ff-only` also fails on a
  detached `~/laika`, but `test/browser/golden/connect.json` snapshots it
  and that test's header forbids regenerating it to go green — filed as
  LAI-1098 rather than changed here.
- Port: none fixed — the browser harness stubs the board on an ephemeral port.

**Verified for real** (throwaway HOME, `zsh -f`): old CLI elsewhere with its
link earlier on PATH → fresh block installs, `laika version` still the old
one, `ln -sf` fix → current commit, old folder untouched. `~/laika` detached
40 commits back → `pull --ff-only` says *You are not currently on a branch*;
the exists block moves it and `laika version` prints the board's commit.
