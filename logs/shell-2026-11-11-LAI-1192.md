**Decisions**
- Search a page of `GET /tasks` client-side, not per keystroke. The API has no text search and `GET /tasks/:id` takes ids, not keys, so per-keystroke requests would return the same page every time.
- Navigate to `/board?project=…&new=task` for Create task rather than calling `CreateTaskProvider` directly. The provider lives inside the space layout, outside the palette's tree, and `?new=task` is its documented entry point.
- Trigger in the sidebar and in the phone bar, not a new desktop header. The header is hidden above 900px, and showing it would change the chrome that PR #291 is reworking.
- Reused `components/typing-in.ts` after the base merge, deleting my own copy, so there is one rule for "typing".
- No Appearance row: no such screen exists ("if present").

**Discovered**
- cmdk 1.1.1 highlights the first row on open but leaves `aria-activedescendant` unset until an arrow press; worked around in the component and asserted in the browser test. Not filed: library behaviour, handled here.
- The proposal's example that Dashboard is gated by `audit_log.export` is stale; the route table no longer gates it.
- Two of my own browser assertions first passed against mutations because a second key press toggled the palette shut again. Each key is now checked on its own; all three mutations (bare-letter guard, typing guard, focus restore) fail the tests.
- Only browser and test servers from the harness were used; no long-running instance or fixed port.
