- Lists page until a page comes back shorter than `limit` and never read
  `meta.paging.total` — CHIEF's live login measured `total: 2` for 25 rows,
  and a total that undercounts would end a read early and the absence
  reconcile would remove what the missing pages held. An incomplete read is
  now a page that fails, which records the error and changes nothing.
- The in-flight guard is a `WeakMap` keyed by the `Db` handle: `index.ts`
  hands one handle to both the app and the scheduler, and two test databases
  never share one — no handle to thread, no global that leaks across tests.
- The pasted token's check reads one page each of `/leave` and `/employee`;
  a `403` on either reads as "sees none of it", not a refusal, so the screen
  can say what the account lacks. Every complete sync refreshes
  `sees_everyone` and `sees_departments` from what it read.
- A pending two-factor sign-in stores the restricted token and names the
  account by its email until the code arrives; the check runs on the token
  the code answers with (Clan refuses every read of a restricted token).
- `two_factor.methods` are served only in the answer to connecting — §4.88
  has no column for them — so a read of a waiting sign-in answers `[]`.
- `hr.sync` is the last job: the boot runs `atStart` jobs one after another
  and this one waits on the network. A failed read throws its code alone, so
  `cron.job_failed` carries no token and no Clan text.
- A changed people mapping stamps that person's live leave `removed_at` at
  once rather than leaving it on the wrong member for up to 30 minutes; the
  next sync writes it under whoever they are now.
- Manual holidays are removed by `removed_at` too, so no holiday row is ever
  deleted; a partial unique index holds one live manual holiday a day.
- `migrate.test.ts`'s `migrations.length + 6` became a read of the journal:
  the count had to be bumped by every migration and was the next to rot.
