**Decisions**

- *Away until…* in the popover is written as an away period from today (the
  server has no `away` status): choosing it adds one, changing its date
  replaces the current period keeping its start, leaving it ends the current
  period. The upcoming periods are listed with × and an Add row.
- The header and Current load share **one** `GET /people/:id/load`: it
  carries the whole record and logs the look once. A reader without
  *See everyone's analytics* gets their row of `/people/availability` — never
  asked of an analytics reader, whose list read would log a look at
  everybody on it. Nothing is asked before permissions settle.
- Columns are drawn from what the server sent (`hours_per_week` present,
  `in_progress` present, `last_2_weeks_minutes` present), not from the
  reader's role, so a D-137 change on the server needs no client change.
- Add to project offers the spaces where `gates.project(id,
  'project.members.manage')` holds — every space for an owner or admin
  (implicit lead), the led ones for a space admin.
- Current load is a full-width card above the summary rather than a column
  card (the design draws it in the grid): its four parts need the width, and
  it keeps `columnPlan` and its tests untouched.
- For you renders nothing when there are no notices (the design draws no
  empty state for it); loading also renders nothing, to avoid a jump.
- `.time-tab` pads the Time tab like Capacity's `.cap`; LAI-1138's report sat
  flush against the rail. `time-report.test.ts` still 24/24.
