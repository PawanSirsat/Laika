**Decisions**
- The reader is a **required** parameter of `daysOf`, `dayOf` and
  `availabilityFor`, not an optional one defaulting to the person — a caller
  that forgot it would otherwise show leave types silently.
- **Named nested shapes** (`OffHolidayView`, `OffLeaveView`, `OnLeaveView`,
  `OffDayEntryView extends OffDayView`) rather than inline objects: the web
  drift guard misreads a multi-line inline object's fields as the parent's,
  and `extends` within the module is followed by both guards.
- **One rule, extracted**, not a second copy: `availability-audience.ts` now
  answers the list and the leave alike, and a test asserts the list lists
  exactly whom the rule says each reader sees.
- **An admin always sees the type**, with or without *See everyone's
  analytics* — D-149 item 5 names admins separately from the grant.
- **Two halves of one status are `part: 'full'`**; the type is the first row's,
  whole before halves, then by id.
- **A `scope_json` that is not a JSON object covers nobody** (fail closed); an
  empty list names nothing, so it does not narrow.
- **Holidays are not narrowed by the reader** (D-149 item 5: the
  organisation's). Leave is the only thing gated by availability visibility.
- The list's own filters (deactivated people and org viewers are not listed)
  are kept as listing filters, not part of who-sees-whom: the grid can show a
  deactivated person with minutes, and their leave follows the space rule.
