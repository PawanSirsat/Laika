- cli/src/attach.ts — `laika attach <TASK-KEY> <file…> [--caption]… [--comment]
  [--harness] [--json]` and `--unlisted <repo> --project <slug>`.
  - It checks every file first: 1–20 files, none empty, no secret. Then it
    finds the task over `/mcp` `get_task_context` (as `laika time` does) and

  - any file with no NUL byte is scanned as text;
  - `.xlsx` and `.docx` files are opened and their text scanned;
  - a key-named file (`*.pem`, `*.key`, `id_*`) is read as text, so a
    certificate passes and a private key doesn't; in binary form it is refused
    by its name;
  - keystores (`.p12`, `.pfx`, `.jks`) are refused by name.

  A refusal names the rule and where (a line, a sheet's row), never the value.

**Decisions**
- Uploads are created without `task_id`; only the one comment links them.
  - The task's exit rule ("anything else means nothing was linked") can't hold
    if each file is created with the key. A file named with its task joins it
    as soon as its own upload completes, so a failure on file 3 would leave
    files 1–2 on the task.
  - With project-only uploads, nothing is on the task until the comment's
    single write. The comment then owns the files, as MCP `add_comment`'s
    `attachments` do.
  - The key is still accepted on the command line and resolved over
    `get_task_context`, which also covers outside ids such as `LAI-1351`.
  - Told the lead before building.
- `--unlisted <repo> --project <slug>` logs a new finding instead of
  attaching to an existing finding by id. The board has no API to add files to
  a finding that already exists; they link only as `log_unlisted_work` logs it.
  Adding a route is a server change for another task. Told the lead.
- The doctor check uses GETs only. Doctor's contract (its test) is GETs only,
  with the token sent only to its own board. The guard was widened by name to
  `/api/v1/org` and `/api/v1/me`, and stays GET-only. A token's read-only scope
  can't be read with a GET, so a read-only token is found out by the upload
  itself.
- The project lookup is behind a dynamic `import()`. A static import of
  `activity-sync.ts` closed an import cycle: activity-store → connect → bridge
  → device → doctor → attach → activity-sync → activity-usage →
  activity-store. That left `DAY_S` uninitialised and broke `laika status`;
  `doctor.test.ts` caught it.
