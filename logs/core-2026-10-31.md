**Decisions**
- Kept the task file's state names (`received`, not the dispatch's `received_by_helper`). The task file and the proposal are the artefacts; renaming would contradict §4.6.
- `accepted` is derived from the offer and not stored. Storing it would be a second copy of §4.73's state that could drift.
- Recipients are fixed when the event is written, and permission is asked again on every read and frame. The alternative, computing recipients at read time, makes "an agent never gets another's offer" depend on every reader's query.
- Acks go over REST only. `agent_sync` is documented in §7.1 as reading and recording nothing, so it gains a read of events but no write.
- No web half. No client type mirrors `InboxItem` or the new page type.
