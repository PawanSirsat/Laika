**Decisions**
- Kept the task file's state names (`received`, not the dispatch's `received_by_helper`). The task file and the proposal are the artefacts; renaming would contradict §4.6.
- `accepted` is derived from the offer and not stored. Storing it would be a second copy of §4.73's state that could drift.
- Recipients are fixed when the event is written, and permission is asked again on every read and frame. The alternative, computing recipients at read time, makes "an agent never gets another's offer" depend on every reader's query.
- Acks go over REST only. `agent_sync` is documented in §7.1 as reading and recording nothing, so it gains a read of events but no write.
- No web half. No client type mirrors `InboxItem` or the new page type.

## 2026-10-31T11:30:00+02:00 — LAI-553 (Codex review of #165)

**What changed**
- server/src/services/agent-events.ts — the ack reloads the actor (`reloadActor`, the LAI-539 per-frame read) inside its `BEGIN IMMEDIATE` and refuses with `TokenAuthError` (401), or 404 for an event the agent may no longer read. The poll computes the projects the agent may read now (one `selectDistinct`, filtered by pin and `project.read`) and puts them in the query, so a page is one query plus look-ahead and `has_more` counts only readable rows. Added a `projectSlug` option.
- server/src/http/routes/agents.ts — `GET /agents/me/events?project=`.
- server/src/mcp/read-tools.ts — `agent_sync`'s events take its `project`.
- server/test/http/routes/agent-events.test.ts — held-body ack regressions (token revoked, grant removed, owner demoted and off the project, plus the unchanged control) and the two-project `agent_sync` regression. 20 cases.
- server/test/services/agent-events.test.ts — the bounded-query test: same statement count with 3 and 60 unreadable deliveries on both sides of the readable one, and `has_more` false.
- docs/SPEC.md §6.4 — the feed's paging is deliberately not §6.3's (numeric `after`, default and max 100, `{cursor, has_more}`), `project`, and the ack's re-read. §7.1 `agent_sync` takes the same `project`.

**Decisions**
- Reloaded with `reloadActor`, not `reloadAgentActor`. The latter demands a `full` token and names only claim and hand-off actions; the ack is presence, and a refusal should match what a new request on that token gets (401), as the stream does.
- Readable projects are derived from the agent's own deliveries rather than its grants, so the filter needs no assumption that grants are the superset.
- `cursor` is now the last returned `seq`, not the last scanned one. Hidden rows are re-filtered on every poll and come back if access does, which keeps delivery at least once.

**Discovered**
- My first held-body test passed against the unfixed code. A streamed body with no `Content-Length` is read whole by `bodyLimit`, before auth, so the hold sat before the actor was resolved. Declaring the length, as real clients do, holds the true window, and the mutation is now killed on all three cases.
- PR #167 (LAI-1011) changes `eventView(row)` to `eventView(row, lens)`. `routes/events.ts`'s agent re-frame calls `eventView(row)`. Whichever lands second passes `activityLens(db, agentReader(current), [row])`. Noted on #165.
