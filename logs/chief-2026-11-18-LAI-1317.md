**Decisions**
- The claim checks wrap `getUserInfo`, not better-auth's `user.validateUserInfo`: that hook
  also runs on `internalAdapter.createUser` outside an endpoint, which is how SSO first boot
  makes the owner, and it would refuse there with `validation_context_missing`.
- A refused token redirects with its own code (a 302 `APIError`, as `c.redirect` makes) rather
  than returning `null`, which better-auth reports as `unable_to_get_user_info` for every
  case; the screen and the tests can then tell them apart.
- Scopes are emptied, not refused: better-auth merges a `before` hook's context with defu,
  which cannot delete a key but does replace an array.
