**Decisions**
- Pairing, exchange, client-report and repo-setup tables are **not** in
  0070. The plan names them under one migration but nothing requires it, and
  an unused table is a SPEC section with no behaviour. Slice C adds them.
- `last_cli_version` / `last_cli_commit` / `last_protocol` left out of
  `devices` for the same reason; plan slice E adds them by `ADD COLUMN`.
- `agents.device_id` FK is NO ACTION, not the plan's RESTRICT: RESTRICT is
  checked immediately, so deleting a user (`invites.ts`, `setup.ts`) could
  fail when its cascade reached `devices` before `agents`. NO ACTION is
  checked at statement end, still refuses deleting a device that has agents,
  and a test deletes a user with both.
- Read endpoints only: rename, confirm, merge, revoke stay with later
  slices; `/agents/devices` and its confirm/revoke are untouched, and
  `confirmed` on a device reads `confirmed_at` **or** a §4.67 row, so the
  old confirm path still shows.
- An agent token reads its owner's devices, as `/agents/devices` already
  allows; narrowing is plan §L6's separate task.
- No Planned mark in SPEC: the table ships in this PR, and LAI-1002
  (four-digit `PLANNED_MARK`) is still in review.
- LAI-1042 has no task file on master, so `depends-on: []`; the plan is
  named in prose.
