**Decisions**
- Framework-free poller and reducer in `home-poll.ts` instead of a `use-*.ts`
  hook — the hook would need a `WEB_NO_MIRROR_REQUIRED` entry in
  `server/test/tooling/structure.test.ts`, outside this task's `server/web/`
  scope, and the rules are unit-testable this way.
- Tasks via `GET /tasks` (every readable space, one walk per open kind) rather
  than *On your plate*'s per-space reads — fewer requests across many spaces;
  the blocked rule matches `plate-derive.ts`.
- Needs your attention draws its three sources independently, so a 403 or
  error on the task list drops only Overdue, not reviews and hand-offs.
- No sorting of empty sections to the bottom (proposal §1.3): fixed positions
  keep focus and screen-reader landmarks stable across a re-read.
- The one-page census was taught the `api.` prefix rather than renaming calls
  to dodge it — renaming would have made those calls invisible to the guard.

**Discovered**
- `GET /tasks` has no `overdue`, `blocked` or `due_before`/`due_after` filter,
  and Organisation → Work has none either, so a cross-space count can only lead
  to a superset list. Server gap (proposal BE-2); not filed here — the id range
  for a polly-dispatched builder is CHIEF's call.
- No org-wide agent or claims read exists (`GET /agents` is own-only); the
  Agents section is "Your agents" (proposal BE-3).
- LAI-237 (*org-wide activity feed unused*) is answered by this task's caller
  of `GET /activity`.
- Mutation check: 13 mutations, one per key behaviour, each turned a named
  test red. The first "Connection lost only from suspect" mutation was
  equivalent and stayed green; replaced with a client-clock rule and a test
  that a `live` session with an old heartbeat stays Connected.
- Browser layout tests must set the viewport before boot (`open`'s `before`):
  the shell picks the rail from the boot width, so resizing after load draws
  the sidebar over a phone layout.
