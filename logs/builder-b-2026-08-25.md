**Decisions**
- *Step 3 is not the design's step 3.* "Invite people and set their roles from
  Org settings" names an API that does not exist (LAI-071) and a screen that
  does not exist. On the first screen a self-hoster ever sees, that is an
  instruction to do something impossible. Wrote a true step instead and asked PM
  to confirm the wording — copy is not mine to invent, but shipping a false
  instruction is worse than proposing a true one.
- *The status panel came back with one line.* It reports the database, which
  needs no endpoint: migrations run before the port binds, so a process serving
  the page has already run them. Everything else waits for LAI-206.
- *`ownsChrome` is route-keyed on purpose*, and the LAI-062 objection does not
  apply: it defaults to absent, so a new route **gains** the shell's chrome
  rather than losing it, and the failure mode is a duplicated header rather than
  a screen with no theme control. The nav gate is still keyed on the session.

**Discovered**
- **The design's overlays only work in one theme.** `rgba(255,255,255,.14)` for
  the step badges, chip border and status rule assumes the rail is dark. The
  rail is `background: var(--tx)`, which inverts — so in dark theme the rail
  goes light and all three overlays disappeared completely. Mixed from
  `currentColor` instead. **Any inverted panel taking literal white overlays
  from this design set will have the same bug**; worth checking `5a` and `7a`
  when LAI-074 and LAI-076 come round.
- **`color-scheme` has to invert with the panel.** The native theme radios sat
  on the rail painting for the *document's* scheme, so on the inverted ground
  they rendered as grey blobs. `.boot-rail { color-scheme: dark }` and
  `.dk .boot-rail { color-scheme: light }` fixes it.
- **AC7's premise was half wrong.** It said the strength meter and the "Matches"
  confirmation both already existed. The meter did; **"Matches" existed nowhere**
  — the confirm field only ever showed an error on mismatch. Built it rather
  than ticking the criterion.
- **The 30px rail mark is a glyph tile.** `Brand` has no glyph, so scaling it up
  and filling it flat produced a blank white square that reads as a broken
  image. Kept the accent mark at its normal size. A real glyph is a design asset
  decision.
- **`--weight-regular` does not exist** — it is `--weight-normal`. Caught by the
  undefined-token guard added yesterday, which has now caught two of my typos.

- *The pattern exemption is `use-*.ts` in three folders, not all `.ts` there.*
  PM asked for a folder exemption; a whole-area hole in the mirror rule is worth
  more than the problem. Narrowed to the one case that genuinely has no home.

**Discovered**

  of six, but no `/orgs` route is mounted in `app.ts` and it falls through to
  `<Screen>`. Applying the rule hid it; special-casing it would have reproduced
  the defect one item at a time. Reported rather than quietly kept or quietly
  dropped — it is a product call.
- **The shells' loading state has a shelf life.** It is honest while someone is
  about to fill them and a lie the moment they are not: a permanent spinner says
  "data is coming" and means "nobody built this". Noted in each file and in the

- **PM's count was four working; it is two.** Board and Projects work today.
  Sprints, Timeline and Dashboard are shells with someone actively on them,

## 03:05 +05:30 — LAI-074 login, design 5a → review

**Changed**
- `server/web/src/routes/screens/LoginScreen.tsx` — eyebrow, tile mark, padlock.
- `server/web/src/components/Brand.tsx` — `variant="tile"` with the glyph.
- `server/web/src/routes/screens/auth.css` — 5a's measurements, custom checkbox.
- `server/web/src/components/Sidebar.tsx`, `test/routes/nav-truth.test.ts` —
  empty-group fix, committed under [LAI-082] (see below).

**Decisions**
- *Literal rems for 9px, 10px and 14px radii.* The radius scale is 4/8/12; the
  auth shapes are one-offs in the design, not scale members. Colours stayed
  tokens (D-020) — the rule is about colour, not geometry.
- *`Brand` gained a tile variant rather than changing the sidebar's mark.* The
  design genuinely uses two marks. AC2 names the stroke colour, which only means
  something if something is stroked, so this one needed the glyph.
- *The checkbox tick is a mask, not a background image.* A data-URI image has to
  hardcode its stroke; `--tx2` differs per theme. Masking paints it with
  `background-color`, so it follows the token.
- *Scoped the custom checkbox to the sign-in card.* Restyling every checkbox in
  the app is a form-language decision, not a side effect of a login task.

**Discovered**
- **I styled a class that does not exist.** `.checkbox-box` — the component
  renders `checkbox-input`. The rule matched nothing, so AC7 would have been
  false-in-fact while the screenshot looked right. Caught by listing the real
  class names instead of assuming them. **CSS that matches nothing fails
  silently and is indistinguishable from CSS that works** — the same shape as
  the undefined-token bug, and the reason that guard exists.
- **LAI-082 left an empty `SETTINGS` heading.** Hiding the unshipped routes
  emptied the group, and the sidebar still drew its title with nothing under it
  — a smaller version of the same lie. Fixed in `Sidebar.tsx` with a guard, and
  committed under `[LAI-082]` since that task is in review and not yet accepted:
  better to send it back corrected than have it accepted with a defect I put
  there. Told PM.
- **A regex guard failed for the wrong reason.** `[^)]*` cannot cross the `)` in
  `filter((group) =>`, so the new test failed against correct code. Widened to
  `[\s\S]*?`. Second time a structural guard's *pattern* was the bug rather than
  the code — worth writing these against the formatted output, not the intent.
