**Decisions**
- The web's one list is `TOOL_CATALOG[].cliSetup`, which
  `tool-catalog.test.ts` already holds to `planFor` by board slug. The new
  test holds it by CLI harness as well, because the check takes the CLI's
  name (`copilot-vscode`, not `vscode`). The web image does not carry
  `cli/`, so the two sides meet in a test, as before.
- `other` (Copilot CLI / Copilot cloud) also gets no command. Before, it got
  a bare `laika project check --project X`, and that records under whichever
  single tool is set up on the device. That is another agent's record, so
  step 3 never showed it for the tool picked.
- `--harness X` with a credential and no project now exits 2. The brief asks
  that an explicit `--harness` that cannot record exits 2 whatever the order,
  and LAI-1090 made `--harness` a request to record. This is flagged in the
  task notes for the reviewer.
- The refused message names `laika agent login <tool>` beside the
  environment variables. `login` accepts any harness and writes the file
  `readCredential` reads first, so leaving it out would be the opposite
  overstatement.
- The exit statement is written once in each of the three places and held
  by a test, rather than generated. A comment cannot import a string.
