**Decisions**
- **Delete now is its own route**, `POST /tasks/:id/purge`. The design sketched `DELETE ?now=true`,
  but a query flag would put "into Trash" and "erased for good" one typo apart.
- **A scrubbed task is `404` to a person too, not only to a token.** Otherwise opening one by link
  would show a *Deleted task* with a Trash banner and a Restore that cannot work.
- **Delete now only from Trash** (`not_in_trash`). It is the second step of a delete, so nothing
  is erased in one click from the board.
- **A space admin only, even for a member's own task.** A member may delete and restore their own
  task, but erasing it is final, and §3.2's *Cancel / delete task* row already gives space admins
  the wider right.
- **Subtasks in Trash go with the parent.** While the parent is in Trash they can only be there
  too, and a subtask can never be restored under a parent that will not come back.
- **The scrub also clears** round summaries, review reasons, checkpoint summaries and file
  names. These are text written about the task, which the design's list did not name.
- **It keeps:**
  - checkpoint manifests and refs, which are git metadata;
  - `member_notices`, which retention removes at 90 days;
  - `email_inbound` rows, which have their own retention;
  - running timers.
- **One task per transaction in the job, at most 500 a run.** A large backlog cannot hold the
  write lock, and the rest wait a day or the next boot.
