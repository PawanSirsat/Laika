**Decisions**
- Lane commits go to a separate file, not `repos`. `buildSnapshot` (the
  heatmap census) reads `repos`, so a builder's repo there would count its
  commits as the owner's contribution, which the decision forbids. In the
  drafter a lane commit is a bare timestamp, so it cannot name a task or
  change how minutes are split.
- The hook finds the top level with a `[ -e "$d/.git" ]` walk and appends
  with one `printf`. My first version called `git rev-parse` and the awk
  prune. That failed the existing contract test that a dispatched
  sub-agent's start forks nothing under zsh (D-095's fork-less test). So
  pruning moved to the sync, and dedupe moved to the reader.
- The person's author emails still filter lane commits. A builder repo can
  hold teammates' commits, and those are not the owner's ticks.
- A person-started turn is counted in `signals.prompts` as well as `at`,
  because the board checks that `at` totals never exceed the count. The
  heatmap is unchanged: no `p` line is written for it.
- Status line: re-running `laika activity on` rewrote state.json without
  `drafting`, while `time-drafts.json` stayed. That is the only writer that
  dropped the field.

**Discovered**
- A lane commit outside every stretch of the person's activity is not shown:
  ticks live on blocks, and making a block would add hours. While polly is
  idle for more than 20 minutes, a builder's commits do not tick.
- Mutation runs: each new behaviour, removed, turns its test red (10 of 11
  first time). The survivor was "a lane commit names no task", which a type
  makes true. I replaced it with a fixture where the person has a session in
  the builder's repo, and a mutation that reads builder commits as the
  person's own now goes red on the task and minutes assertion.
