**Decisions**
- **The device row is made at completion, not at approval.** The plan's
  approve "creates or updates the device". Doing it at completion means a
  device row with a key exists only once that key has been proved by its
  signature. Approve answers the request, not a `DeviceView`.
- **Pairing never changes an existing device's kind.** Attaching to an
  imported device whose kind differs is `409 device_kind_mismatch`. A local
  device turned cloud would hold tokens the 24 h rule forbids. A *new* paired
  `cloud` device gets `kind=cloud`, and a test proves that registering on it
  without a ≤24 h expiry is `422 cloud_token_expiry_required`. This answers
  the LAI-1045 reviewer's note.
- **The signature is checked before the state is told.** A caller without
  the key learns only that the id exists. Five bad signatures cancel the
  request.
- **The code is `XXXX-XXXX`**, Crockford base32, 40 bits. The plan's
  example showed an `LK-` prefix; CLAUDE.md §5.1 calls `LK-` stale, so it is
  dropped.
- **The code is hashed with plain sha256**, as plan §D.2 says, not an HMAC.
  It lives ten minutes.
- **Device routes call no `can()`**, on the `consumeResetLink` precedent: no
  actor exists, and the code or the key is the whole authorisation. CLAUDE.md
  §5's list of exceptions is exhaustive (it became three with D-123 during
  this task), so **whether this is a fourth is for CHIEF**. No §3.1 action
  was invented.
- **No general `LaikaDevice` header verifier.** Plan §E.1 needs a SPEC §6.1
  paragraph from CHIEF for it, and nothing in C1 uses it. Completing signs
  over the body. C2's redeem can build on `device-signature.ts`.

**Decisions**
- **The claim bucket (120, 20 a minute) is larger than the failure budget
  (60, 10 a minute)**, so the failure budget is what stops a guesser, and a
  test can tell the two apart.

- **Eviction can reset a spent bucket.** Buying that takes 50,000 requests to
  new keys, and it only ever gives back budget.
- **The key index covers revoked devices too**: a key paired once is never
  proof for a second device.
- **The public URL is refused, not guessed**, on the device's side as well,
  because a completing device signs the origin.
