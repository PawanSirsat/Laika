**Discovered**

**The MCP tool name is not the obvious one.** `mcp__plugin_laika_laika__<tool>`,
not `mcp__laika__<tool>`. A wrong `allowed-tools` value **fails as an unexplained
permission prompt rather than an error**, so nothing would have said so.

**The tool returns two payloads and the client's choice varies.** A rendered
`text` block and `structuredContent` with ULIDs. My instruction was corrected
twice — *"returns markdown"* → a run said *"raw JSON"*; *"show the text block"* →
the next said *"only the structured payload this time"*. **Both were true of the
wire and false of what the agent held.** The rule is now about the output —
display keys, never an id — which holds either way.

**Two of my assertions could not tell explaining from doing.** One forbade the
word `password` and failed on the text explaining that `npx laika init` asks for
one; the other failed on a **line break** inside the phrase it matched. Second
and third instances after LAI-157's `heartbeat`.

**And my LAI-436 fixture had a six-day shelf life.** It pinned the "current"
sprint to one ending 6 September; the screen decides *current* against
`Date.now()`, so on the 7th three assertions failed — **in the gate, not in
review**. Anchored to today now, which is what it always meant: *"a sprint
containing today"* is the property; a date only happened to be that in the week
it was written. `timeline-bars.test.ts` has fixed dates too but asserts only bar
shape — latent, not broken, left alone.
