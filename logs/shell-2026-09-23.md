**Decisions**
- **The column name is the label; the status stays the value.** The owner asked
  whether renaming a column should rename the status. Half yes: the card must
  read the column's name. Half no: `TASK_STATUSES` is a fixed enum the REST
  API, the policy layer and the MCP tools depend on by literal value —
  `laika_finish_task` moves a task to `review`. Rewriting it would break every
  agent integration and every `?status=review` link.
- **Only the lossless case substitutes.** One status per column means the name
  identifies it exactly. The shipped default merges `todo` and `backlog`;
  substituting there would render two statuses identically.
- **Filed the server half rather than crossing** — LAI-618.

**Discovered**
- **The API produces the state it refuses.** `PUT .../statuses {"statuses":[]}`
  is a `422`, but taking a status into another column empties the loser and
  returns `200`. Validation guards the column being *written*, never the one
  silently losing one. That is how a `BACKLOGS` column came to hold nothing.
  A test asserting `[] -> 422` passes forever while this is broken.
- **The dialog already named the source column** — I reported otherwise before
  reading it. What it never said is that the source would be left empty.
- **The deploy path was in `docker/aws/laika-ec2.yaml` all along.** I looked
  for SSH, found none, and told the owner I had no way in. Port 22 does not
  exist **by design**; access is SSM Session Manager and the box pulls from
  ECR. Looking for one mechanism and concluding none existed.
- **A one-time gate red I could not explain and did not fix.**
  `environment-posture.test.ts` failed once in a full run, then passed 3/3 in
  isolation and in the full gate. My first hypothesis — an untracked
  `.laika-local/` — was **disproven**: it passes with that directory present.
  Most likely it raced a concurrent `pnpm build`. Recorded, not claimed fixed.
