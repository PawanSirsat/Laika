- Fixed the post-setup race with `markComplete()` rather than awaiting a re-fetch. A 201 is definitive — asking the server again to learn something it just told me is both slower and, for the frames in between, wrong.
- Removed the presence toggle instead of keeping it and dropping the value. A control that silently does nothing is worse than an absent one, and PM's note said so explicitly. Filed LAI-207 because this reverses part of LAI-021's accepted criteria and should come back properly.
- Removed the status panel rather than feeding it zeros. A panel confidently reporting `0/0 applied` is worse than no panel because it is believed. Filed LAI-206; the component is untouched and still tested.
- Gave `setup.ts` a real mirrored test rather than an exemption when my own structure check flagged it. The exemption list exists for modules that genuinely cannot be unit-tested; reaching for it because it is quicker is how that list rots.

**Discovered**
- **The first screen a new instance shows anyone was a 404.** The server redirected to `/setup`; the SPA routed `/first-boot`. Nothing had connected the two because until this task nothing followed the redirect. Worth remembering that a constant shared across a boundary needs a test that reads it, not one that repeats it.
- **My first 422 test proved nothing.** I used a blank org name, which my own client validation catches — so I was watching my message reach my own field. Finding an input that passes the client and fails the server (`ada@example..com`) was the only way to prove the server's message reaches the right input. Second time this session I have written a test that did not exercise the thing it claimed to.
- **The post-setup race made success look like failure.** 201 returned, session live, chrome showing `owner` — and the URL still `/setup`. An async `recheck()` left the flag stale for a frame and the redirect effect bounced it back. Easy to misread as "setup didn't work" and go looking in the wrong half.
- **My own LAI-039 structure check caught this task one task later**, on both new modules. First time a guard I wrote has bitten me on unrelated work, and it was right to.
