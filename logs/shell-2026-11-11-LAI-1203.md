**Decisions**
- Blur validation waits for text in the field, rather than firing on every
  blur. A required error on a field the reader has not reached yet is noise,
  and submit still catches it.
- The first invalid field is read from the DOM (`[aria-invalid="true"]`), not
  from a list of names, so a server-mapped error counts the same as a client
  one and the order cannot drift from the screen.
- The show/hide toggle keeps its `aria-pressed` and its Show/Hide label (both
  asserted by `forms.test.ts`). I added `aria-controls` rather than reworking it.
- `AuthCard` passes `data-*` attributes through, so `person-admin.test.ts`
  keeps `data-reset-state` unchanged.
- No ⌘K hint on the 404: there is no palette on this branch.

**Discovered**
- `getByLabel(…, { exact: true })` misses these fields, because the label text
  includes the required `*`. The new tests find the control by the label's own
  text instead.
- Playwright's `CapsLock` press does not reach `getModifierState`.
