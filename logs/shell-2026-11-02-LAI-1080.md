**Decisions**
- One host component for both tabs rather than two that each read `/devices` —
  the numbers on Devices and Tools cannot disagree, and the device → tool wizard
  hand-off keeps its state across the tab switch.
- *Show revoked* is per tab: Devices adds revoked devices, Tools adds revoked
  tools — rather than one count that mixed both and, toggled, showed tools on a
  tab that no longer has tool rows.
- The device panel's tool rows read readiness too (`listedStatus`), so a tool
  says the same word in the list, the device panel and its own panel.
- Busy actions in the panels are `aria-disabled`, not `disabled`: the
  confirmation hands focus back to the button that asked, and a disabled one
  cannot take it (the first run failed exactly there).
- Closing after a disconnect reuses the panel's close (Back or replace) and the
  restore falls back to the list heading when the row went.
- `toolAddress()` in overview-state.ts left alone (the lead's instruction; the
  Overview builder owns the rest of the file and will point it at Tools); the
  alias lands the old address with one replace.

**Discovered**
- Two `useDialogFocus` traps stacked (panel + confirmation) pinned Tab on the
  confirmation's first button: both capture listeners ran, the panel's pulled
  focus in, the confirmation's pushed it back to its first control. Fixed in
  the hook; any future modal-over-modal gets it.
- A secret shown once in a tool's details (the browser rotate) goes with the
  panel if it is closed before *Done* — the row used to stay mounted. Same
  only-copy warning as before; worth a guard (confirm close while a secret is
  held) if the owner wants one. Not filed: reported to the lead.
- Opening a wizard pushes and closing it replaces (pre-existing), so Back after
  a wizard lands on the same list twice. Unchanged here.
- Test stubs answered `/verification` with `{agent_id, client_report}` only;
  readiness needs the whole shape, so the fixtures now serve what the board
  serves.
