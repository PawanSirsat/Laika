**Decisions**
- One action, `profile.read_own`, for both own reads — for the person there is nothing to split the profile and heatmap on, unlike `profile.read` / `profile.activity.read` which are about somebody else.
- Own `ratings` are gated with `can(actor, 'profile.read')` — the owner always, a granted role too; a plain member never sees them.
- `PATCH /users/:id/profile` goes through `getProfile` and so is logged like the `GET` — it answers the same profile, and the conservative reading of D-102 rule 3 is that a read that reveals the data is a look.
- The `time` look carries `day: null` (a range), matching `GET /people/:id/time/summary`.
- `minutes_14d` reuses `summaryOf` over the person's last 14 days by `todaysFor` (place, else UTC) — the same assembly as `GET /people/:id/load`, so the two cannot disagree. Rows still come only from membership/assigned task/decision; time in a project alone does not add a row.
- `due_7d`: open (backlog/todo/in progress/review) tasks with `due_on` from the person's today through today + 6, overdue excluded.
- `?since=` narrows both the page and `total`; without it `total` counts every kept look. `total` is always present.
- Web types declare the new fields optional — fixtures written before them would otherwise need editing, and that is LAI-1152's screen work.
