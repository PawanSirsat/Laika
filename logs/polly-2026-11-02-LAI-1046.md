**Decisions**
- **Revoke: the plan's §E.4 choice.** `token.revoke_any` is kept as a token revoke, and the copy says exactly what stops.
  - I rejected routing to agent revoke. It changes what an admin action does, which is a policy change the task forbids.
  - "What stops" was checked in the code, not assumed:
    - `/mcp` re-resolves the actor on every request.
    - Event streams re-check the token before each frame (LAI-539).
    - `revokeTokenRow` never touches `agents` or `agent_sessions`, so claims lapse at the end of their lease.
  - When the agent has another live credential, the copy says the tool keeps working.
- **`agent_label` uses the server's harness slug** (`claude-code · Belka`), like the precedent in `claims.ts`. The server has no product-name table, so the web turns the slug into *Claude Code* with the existing `harnessName`. I rejected adding a second harness-name table to the server, because nothing would check it against the web's copy.
- **`name` is left as it is for admins.** SPEC §4.9 grants owners and admins (`profile.read`) the names of a person's tokens, registered agents included. Hiding it would change visibility policy. The admin UI shows the label instead of the name, which matches D-120's display rule, and the browser tests assert the name is not rendered.
- **Admin lists group on the client; only the Tokens screen filters on the server.** The admin views need both groups, so one unfiltered request is enough. It also keeps the existing path-keyed browser stubs valid.
- **Kind helpers treat a missing field as personal**, so a reply from an older server cannot drop rows from a grouped list.

**Discovered**
- LAI-1047 and LAI-1048 had been taken by other V3 builders since dispatch. L6 is therefore filed as **LAI-1049** (LAIKA-903), discovered-from LAI-1046.
- The `token.created` activity payload carries the token `name`, which for an agent is its registered name. Audit readers (owners and admins) already hold `profile.read`, so this is not a leak under §4.9 as written. Not filed; noted for whoever revisits D-120 naming.
- `ProfileAgentToken` (`services/profiles.ts`) is a separate profile type, not a `TokenView`, and is untouched here.
