**Decisions**
- No server change: every element in the design has a field the page already read (`GET /usage`, `GET /users/:id/usage`, `GET /me/token-alerts`, `POST /me/token-alerts/:id/dismiss`, `GET|PUT /me/plan-limit`). *Dismiss all* is one dismiss per alert; a bulk route was not worth a server change for a personal, soft list.
- Breakdown panels stay in the DOM, hidden, so a tab is a view and never a request, and existing assertions on each section still read them.
- *Budget alerts* is the reader's own token alerts (the shell's list, so the rail badge agrees), not `usage.budgets`, which stays in the Budgets card a lead sets them in.
- Budgets is not in the design; kept below accepted cost rather than dropping a lead's way to set a budget.
