**Decisions**
- **One icon at a time**: an emoji set over an image drops it (and its object); completing an image clears the emoji; DELETE clears both. Otherwise removing an image would resurface a forgotten emoji.
- **Stateless ask/complete**: the upload id is a ULID in the key `p/<project_id>/icon/<id>`; nothing is stored between the two. Known limit, in D-152: an upload put and never completed stays in the store (≤ 1 MiB, owner/admin only).
- **`immutable` only for the current version**: a URL whose `v` is not the icon's `icon_updated_at` gets `private, no-cache`, so an old link cannot pin an old picture.
- **`project.icon.write` is `isAdminUp`, not a grant**: the owner named owners and admins; no capability carries it. Asked on top of `project.settings.edit` on PATCH.
- **The look store** (`api/project-looks.ts`): every project read is remembered by slug, so the ~60 sites whose endpoints send only `{slug, name}` draw the right mark without any view growing a field. **Icon** from the store whenever known (only Space settings changes it, and it tells only the store); **colour** from the site when it has one (a settings save hands the page the newest copy, and a list reloaded just before must not paint over it — found when `space-settings` "Save sends only what changed" went red). An answer older than the one held (`updated_at`) is ignored.
- **The glyph is CSS, not text** (`::before { content: attr(data-glyph) }`): with the letter as text, every row the mark leads read `AAcme Billing` / `L\nLaika` to tests and to copy-paste. Five browser assertions the builders predicted would go red were green after this, without touching them.
- **The Icon row saves outside General's form** and hands the screen nothing, so an icon change never resets a half-typed name.
