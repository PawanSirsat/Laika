**Decisions**
- No manifest → proceed and let the device route's answer decide, not refuse
  up front — the task file says keep the answer-based fallback, and a board
  without the manifest (pre-LAI-1043) cannot have the device routes anyway, so
  the answer refuses with nothing kept (tested).
- Manifest that does not answer (5xx, network) → refuse, not fall back: a
  board that has a manifest and cannot serve it is not an old board.
- The stub counts the manifest `GET` separately from `received`, so every
  existing "sent nothing" assertion still means "sent nothing of this machine's".
