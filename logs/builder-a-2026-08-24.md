**Decisions**
- **TypeScript pinned to `~6.0.3`, not `7.0.2`.** `typescript-eslint@8.67.0`
  declares `typescript: ">=4.8.4 <6.1.0"`. TS 7 is the native (Go) port and sits
  outside that range, so choosing it would have silently cost us the type-aware
  linting this task explicitly requires. 6.0.3 is the newest the linter supports.
  Revisit when typescript-eslint ships TS 7 support — it will want a task.
- **`format` is a *check* script, `format:fix` writes.** AC4 requires
  `pnpm format --check` to pass; `prettier --write . --check` is a hard error, so
  a write-by-default `format` could never satisfy it. Prettier tolerates the
  duplicated `--check`, so both `pnpm format` and `pnpm format --check` work.
- **Prettier ignores Markdown entirely.** The globs are code+config only. A
  repo-wide `prettier --write` would rewrite `docs/`, `CLAUDE.md`, `.tasks/**`
  and other sessions' logs — every one of them outside my area and hand-wrapped
  to 80 columns deliberately.
- **`pnpm-lock.yaml` excluded from Prettier via a negative CLI pattern**
  (`"!pnpm-lock.yaml"`) rather than a `.prettierignore`. LAI-001's scope
  exception lists eight root files and `.prettierignore` is not among them;
  a CLI pattern gets the same result without creating an unauthorised file.
- **`dev` and `build` are `pnpm -r --if-present` pass-throughs.** No workspace
  package defines them yet. The alternative — inventing `server/src/index.ts` so
  `tsc` had inputs — would have written a file LAI-002 owns. Empty-but-correct
  beats colliding.
- **`node-linker=isolated` (pnpm default, set explicitly).** It is what makes
  "the lint passed because eslint got hoisted" impossible; worth stating rather
  than inheriting.
