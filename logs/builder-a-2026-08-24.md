**Decisions**
- **`createApp()` is separate from the bootstrap.** Hono's test client needs the
  app as a value; a factory that also called `serve()` would make every HTTP test
  open a real socket. This is why AC9 is cheap and AC7 is possible at all.
- **`publicDir` and `fallbackDocument` are injectable options.** Without that,
  "the fallback works on a clean clone" is untestable on a machine that has ever
  run a build — the test would pass or fail depending on local state. Tests point
  `publicDir` at a directory that does not exist, which *is* the clean-clone
  condition. Rejected the alternative of deleting `server/public/` in a test
  fixture: destructive, and racy across parallel test files.
- **Paths resolve from `import.meta.url`, never from `process.cwd()`.** cwd is
  `server/` under `pnpm dev`, the workspace root under `pnpm test`, and `/app` in
  the container. Anything anchored to cwd works in exactly one of those.
- **`details` is always present in the error envelope, `null` when empty.** A key
  that sometimes vanishes makes every client feature-detect it. §6.3 lists three
  keys; this keeps all three, always.
- **The request id is echoed to the client only on 5xx** (§13.2) but set as an
  `X-Request-Id` header on every response. Inbound ids are honoured for proxy
  correlation, but length-capped at 128 and character-filtered — that value lands
  in log lines, and an unbounded attacker-controlled string in a log is how log
  injection starts.
- **CORS denies all cross-origin by default.** Same-origin in production,
  Vite-proxied in development. Widening it should be deliberate.
- **Static traversal is clamped, not rejected.** `/../package.json` normalises to
  a path *inside* `public/` rather than erroring. My first test asserted `null`
  and was wrong — the invariant worth testing is containment, so the test now
  asserts the result is never above the root. Null bytes and malformed
  percent-encoding are still rejected outright.
- **The git-backed LAI-016 tests skip when there is no work tree.** A Docker
  build context has no `.git`; a test that cannot run there should say so rather
  than fail.

**Discovered**
- **Hono routes only `Error` instances to `onError`.** A handler throwing a
  string or a plain object bypassed the error handler completely — under
  `@hono/node-server` that is an unhandled rejection and a dropped connection,
  not the `internal` envelope AC4 asks for. Found by a test written to check
  exactly that, and fixed with an `errorBoundary` middleware. This is a sixth
  middleware in a §11.2 chain that says "fixed order", so I flagged it at review
  as a visible deviation rather than burying it.
- **`SIGTERM` under `tsx` exits 143 and never runs the shutdown handler.** tsx
  forks a child and does not forward the signal. Under plain `node` the same code
  logs `shutdown.start` → `shutdown.complete` and exits 0. This cost me a
  confusing ten minutes staring at a correct implementation, and it is a live
  trap for LAI-008: a container whose entrypoint is `tsx`, `pnpm start` or a
  shell wrapper will have `docker stop` escalate to `SIGKILL` on every single
  deploy. → **LAI-019** filed with the finding written out.
- **§6.3's error vocabulary cannot express `413`**, which `bodyLimit` — mandatory
  on every route per §13.1 — now produces. There is no `405` either. I preserved
  the accurate status and reported the nearest code beside it; forcing agreement
  would report a `405` as a `422`. → **LAI-017** filed (area: docs).
- **Security headers (§13.1) had no task carrying them.** Not in LAI-002's
  criteria, not in LAI-006's. Left out deliberately — CSP depends on what Vite
  emits, and a policy guessed before the SPA exists is a policy that gets
  loosened the first time it breaks. → **LAI-018** filed.
- Node 22 runs the TypeScript sources directly under `--experimental-strip-types`
  once imports carry `.ts` specifiers. Useful to know, rejected as a production
  path, noted in LAI-019 as a fallback.

**Decisions**
- **Built all 14 tables, not the 11 the task lists.** AC4 requires every §4.13
  index, and five of them name `sprints`, `unlisted_work` and `meeting_reviews`;
  §4.5 also gives `tasks` a `sprint_id` FK. D-011 says the spec wins over a task

- **Append-only enforced twice**: a repository with no mutation path *and*

  invisible to Drizzle") — the task asks for a failing attempt, and absence of a
  method cannot produce one.
- **`ON DELETE SET NULL`, never cascade, for activity's project and task FKs.**
  An audit log that erases its own history when a project is deleted is not an
  audit log.
- **`BEGIN IMMEDIATE` for task numbering, and the number derived inside the
  inserting transaction.** Gapless because a rollback consumes nothing; a
  counter table would leak a number every time.
- **Tests run against a temp *file*, not `:memory:`.** WAL is unavailable for
  in-memory databases, so testing there would exercise a journal mode the server
  never uses — and the interesting concurrency behaviour is exactly the part WAL
  changes.
- **Concurrency tested with real worker threads.** better-sqlite3 is synchronous;
  nothing single-process can produce the interleaving that matters.
- **`db:generate` also runs Prettier over the migrations folder**, because
  drizzle-kit rewrites its metadata JSON unformatted every time.
