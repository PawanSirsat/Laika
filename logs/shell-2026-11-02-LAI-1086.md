**Decisions**
- The CLI notice is for a person at a terminal only (stderr a TTY). That is stricter than "never on hook or MCP paths", and it means no harness, script or existing test that pipes output can ever see it.
- "Newer" is git ancestry, not "different": a board commit the checkout has never fetched counts as newer (the usual case after a deploy); a board behind the CLI, or on another line, says nothing.
- The guide is a native disclosure, not a second modal: it nests inside the tool panel and the wizards without a focus-trap fight, and is drawn (and the board asked) only when opened.
- `tool-readiness.ts` untouched (LAI-1088 owns its copy and rule): `readiness()` keeps its own words, and a test drives every branch and pins each word to the vocabulary.
- The chip tooltip is fixed to the viewport: anchored to the chip it ran 256 px off screen at 390 px (the 390 px test caught it), and the card's `overflow: hidden` would clip it under the last row.
- After LAI-1088 merged (a87bfafb), the legend's Ready and Connected say its rule for a tool whose MCP client names no tool (Omnigent, Hermes): Connected until the helper's report says which tool it is. The chip's next step is the checklist's own line, word for word, so they cannot disagree.
