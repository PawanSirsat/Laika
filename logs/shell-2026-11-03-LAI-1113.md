**Decisions**
- **`permissions` is checked against the argv, not used to build it.** The
  launcher's rule is that the argv is the config's array, exactly; so `enable`
  builds the argv and the loader refuses a mismatch either way. That makes the
  opt-in real: hand-editing `--dangerously-skip-permissions` into the argv
  without the key is refused.
- **Unset keys are off.** A file written before this change loads with no
  notification, no window and the allowlist; `enable`'s defaults are yes,
  yes, allowlist.
- **`laika` is its own config key** rather than derived at run time, so the
  only two values in the Terminal line are the config's path and the ULID, as
  the request asked. It is held to `argvProblem`'s program rules.
- **`on run argv` for both scripts**: the AppleScript source is constant, so
  quoting AppleScript never arises; the shell line inside `do script` is the
  only quoting, single quotes on the path.
- **Skip keeps `--permission-prompts none` out**, as the request said ("instead
  of"); the docs say a `-p` run denies anything that would still prompt in
  that mode anyway.

**Discovered**
- The docs say deny rules hold in `bypassPermissions` — the request's worst
  case did not arise — but a Bash deny rule never was a boundary (same finding
  as LAI-1111's branch-protection note).
- The Write tool turned `\u2028`/`\u2029`/`\u202E` escapes in file content
  into the literal characters (a JS regex literal broke on U+2028); fixed by
  rewriting the escapes, and every changed file was scanned for literal
  control and bidi characters before committing.
- The installed `laika` on Belka (`~/.local/bin/laika`) is the `~/laika`
  checkout; a Terminal viewer needs that checkout to have this change.
