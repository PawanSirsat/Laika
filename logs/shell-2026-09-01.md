**Decisions**
- *Most recently active, not most recently opened.* `last_activity_at` is
  already on every `ProjectView`, so it costs no request and answers "where is
  work happening" rather than "what sorts first". Rejected `localStorage`: the
  Notes are right that the selection lives in the URL, and a stored fallback is
  the ambient selection under another name — two browsers would disagree about
  what a bare `/board` means.
- *`/members` asks rather than resolving.* AC2 permits either. A board with no
  project is better resolved than refused; a members list silently scoped to a
  project you did not pick is a permissions screen showing the wrong
  permissions. Flagged on the task for CHIEF to overrule if they disagree.
- *`orgLevel` marks the exceptions, carrying the project is the default.* The
  same inversion as `Route.public`: forgetting to mark a new route keeps the
  reader's context, which is harmless. The opposite default loses it silently,
  which is this defect.

**Discovered**
- *An existing test asserted the presence of the bug.* `routes.test.ts` "nav
  items are real links" matched `href={route.path}` **verbatim**. Its stated
  intent — anchors, not click-handler divs — is right, but it pinned the exact
  expression that was the defect, so it would have **blocked the fix while never
  catching the bug**. Rewritten to assert an `href` expression plus the absence
  of a div-with-onClick. Same shape as the `nav-truth.test.ts` gap the task
  names, one level down: green, specific, about the right subject, and pointed
  at the implementation instead of the property.
- *`BoardScreen` could not use the shared rule at all.* It imported a **second**
  `listProjects` — `api/tasks.ts:263` returns a narrow `ProjectSummary` with no
  `last_activity_at` and no tombstone handling. Two client functions, same name,
  one endpoint. Board now uses the real one; filed as **LAI-226** rather than
  collapsed here. `view-type-drift.test.ts` does not catch it because
  `ProjectSummary` is paired with nothing.
- *Typecheck caught four things the tests could not.* Two screens destructured
  only `params` and not `setParams`; three imports went unused; and Board's type
  mismatch is what exposed LAI-226. `node --test` never loads a `.tsx`, so none
  of it was visible to 518 passing tests.
