**Decisions**
- A token of any kind is refused the three actions, in `can()`, before scope —
  not a route check like heartbeats' `token_required`: `can()` is the one
  authority, and the matrix and drift tests can then see the rule.
- Setting the kind writes no `activity` row — a verb would rebuild the
  append-only `activity` table, against the additive-only rule. Recorded in
  D-078 rather than left implicit.
- `users.profile_kind`'s CHECK added as a column constraint on `ALTER TABLE …
  ADD` instead of drizzle-kit's rebuild of `users` — which, as generated, also
  `SELECT`ed a column the old table did not have.
- "Accepted" and "sent back" count only someone else's move, so a person
  closing their own task is not "accepted"; cycle time keeps `metrics.ts`' rule
  per assignee. Both written into SPEC §6.4 so a reader does not have to guess.
- The manager's blocks are absent from the response, not hidden by the client:
  the kind changes what is served, and the screen draws what it gets.
- *Work by person*'s profile link sits beside the row, because the row is
  already a link to the board.
