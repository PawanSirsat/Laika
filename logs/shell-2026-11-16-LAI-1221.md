**Decisions**
- **Title rule: the header carries the way to the page, the page keeps its
  one h1.** Dropping the h1 would leave each page header's description, tabs
  and controls under no title, and a space and a profile already carry their
  name in the header. So: a screen whose own header draws the h1 says so,
  and the app header shows *Organisation › section* and never a step that
  says what the heading says (Organisation's h1 *is* the org name, so there
  the root goes too). Screens with no heading of their own keep the page step
  as `aria-current`.
- **Shortcut scheme: Alt/⌥ + 1–5**, fixed per destination (My day 1, Inbox 2,
  Insights 3, Organisation 4, Developer access 5), read from `event.code` (⌥2
  types ™ on a Mac). *G then letter* was refused: My day's G sets General, and
  D W M Y N T J K X are all My day's, J K A S the Review dialog's, `c` a
  space's, `.` the Workroom's. A digit with Alt is nobody's, now or when a
  screen grows a letter. Never while typing (`typingIn`), never over a modal,
  only for destinations drawn. Caveat: Chrome and Firefox on Linux take Alt+N
  for tabs; the palette and sheet list the keys and ⌘K reaches every page.
- **`?`**: the app sheet opens on `?` only where no screen claims it; My day's
  help button carries `aria-keyshortcuts="?"` and keeps its own sheet (LAI-1223
  confirmed My day's full list; none is shadowed). The header's ? button opens
  the app sheet anywhere, and the sheet has a My day section held to My day's
  own table by `shortcut-sheet.test.ts`.
- **Theme and person menu live in the sidebar footer only**; the header adds
  no avatar or theme switch (two doors to one room, LAI-1188's reason for
  removing the sidebar search). The palette keeps *Switch theme*.
- **Notifications sources**: `/me/notices` (server read state — opening one
  marks it read, *Mark all* calls `read-all`), review items with `can_decide`,
  hand-offs (`received` + `needs_approval`, read only when the shell's counts
  say there are some), open unlisted work (only `audit_log.export` — the
  shell's count gate is the load-bearing one, the bell's is a second line),
  token alerts. No @mentions: no endpoint addresses them to a reader.
  Per-device *last seen* in `laika.notifications.seen.<userId>`.
- **Live**: the bell listens on the open space's stream through
  `subscribeToEvents`, which is ref-counted per slug and already held by the
  shell, so no new EventSource (asserted in the browser: one source on a
  space page with the bell open). Elsewhere the shell's 60 s polls.
- **Badge from what the shell already holds**: no request on page load
  beyond the hand-off/unlisted lists when their counts are non-zero; the
  notices list is read when the popover opens. The model reads every row
  field-defensively — a partial review fixture (capacity-org.ts) crashed the
  whole app through the badge before that, which is the failure a header on
  every screen must not have.
- **+ Create** hides on phones (the space's own Create and the palette's
  *Create task* remain); the ? button too (no keyboard). Create reads the
  spaces list only when its menu opens — `useSpaces` fetches per caller.
- Recent stores ids only (path, slug, task id + key + space slug, user id),
  validated on read; titles never written.
