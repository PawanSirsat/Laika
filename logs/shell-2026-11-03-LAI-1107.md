**Decisions**
- A fetch failure is transient unless git says the ref is missing — rather
  than listing network errors. A positive list misses the next phrasing; the
  negative test keeps the one answer that is final (the deleted-tag e2e test
  and a new unit test hold it at exit 1). The cost: an auth failure is retried
  at the 15-minute cap until fixed instead of being dropped.
- 401 on the inbox or checkpoints stays a refusal (exit 1), not 75: a revoked
  token does not pass by waiting, and the launcher's `/me` check already ends
  that credential.
- Any record without the marker counts as the owner's, whatever its status —
  not only `prepared`. A pre-LAI-1107 launcher's own leftover record therefore
  reads as hand-prepared and is not started; fail closed, once, on upgrade.
- `worktreeProblem` is a required dep, not optional: an optional one absent
  would have to either skip the check or refuse every reuse, and both are
  silent. Fixtures supply `() => undefined`.
- `spawn_failed` leaving its session to lapse is the same defect as the throw
  (a session opened for an attempt that never started); swept and fixed with
  it rather than filed.
- The existing *starts nothing when prepare refuses* test asserted
  `runs/<offer>/` absent; the requested marker makes it exist. Narrowed to
  "only the marker is there".
