**Decisions**
- Kept the row shape as it was. I did not add `project_name`. The rows already
  carry `project_id` and `project_slug`. The owner's plan says "same row
  shape", and the dispatch says the web maps project ids to names itself.
  The task's acceptance criterion says "plus the project's slug and name". The
  slug is there and the name is not, and I said so on the card.
- No pagination, the same as the per-project read: SPEC §6 says "not
  paginated" for it. Adding §6.3 cursors to the read with no project would
  give one endpoint two different response envelopes. The volume is bounded,
  because the read returns only the caller's own records.
- Newest first sorts on `desc(id)`, not `checked_at`. `checked_at` is answered
  null while presence is off. Sorting on the stored value would still put
  rows in time order, which leaks what presence-off hides.
- Reused `visibleProjectIds` (services/activity.ts) rather than writing a
  second loop. It asks `can(withProject(actor, id), 'project.read')` for each
  project, the same question `requireReadableProjectBySlug` asks, so an
  agent's grants and the org-role rules apply exactly as they do in the
  per-project read.
