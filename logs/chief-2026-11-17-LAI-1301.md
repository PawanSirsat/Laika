**Decisions**
- `attach.ts` is kept free of TipTap — `TaskMarkdown` and the section need `isAttachmentUrl` and the glyphs on the board, and importing the bridge would pull the editor chunk into it (the LAI-827 split, which `task-panel-editing.test.ts` checks).
- In the Markdown view the snippet is written by the bridge, not by hand-escaping — a hand-escaped `report\_v2.pdf` would read back differently from what the rich view writes and pin the text in Markdown for good.
- `paste.ts` keeps an attachment `<img>` (deviation from the criterion's literal "still strips"): cut-and-paste of a screenshot inside the editor would otherwise lose it. The intent of the criterion — no request to anyone else's server — still holds; every other image is dropped.
- A paste that also carries text is the text: spreadsheets and documents put a picture of the selection on the clipboard beside the words, and uploading it would replace a pasted table with an image.
- Save and Create task wait while a file is uploading, rather than sending text that cannot link a file still on its way (it would be swept after 24 hours).
- The upload is `api/attachment-upload.ts`, not LAI-1300's `api/attachments.ts`, as CHIEF asked, so the two builders never edited one file.

**Discovered**
- `@tiptap/extension-paragraph` 3.32.0 unwraps a paragraph whose only token is an image to the image itself — fine for a block image, schema-invalid for an inline one, so a screenshot on its own line opened the whole text as Markdown. Fixed here by keeping the paragraph (`keepImageInParagraph`); worth knowing for any later inline node.
- A two-tone PNG deflates to a few hundred bytes — a "too big" test built from it was not too big. Measured, and the test uses a 5 KB buffer.
- A live-frame test cannot pass until `attachment.*` is in `STREAM_TYPES`: the shared `EventSource` only listens for the names listed. LAI-1300's mirror adds them.
