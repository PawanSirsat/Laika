## 2026-10-21T13:58:45Z — LAI-853 (built on Strelka)

**What changed**
- server/web/src/routes/screens/task/editor/markdown-bridge.ts — `parseMarkdown`
  drops a text block's continuation-line indentation (`withoutLineIndents`), as
  CommonMark does; `sameMarkdown` forgives the indentation of a paragraph
  continuation only (`unindentContinuations`, `layoutOf`)
- server/web/test/routes/screens/task/editor/markdown-bridge.test.ts — two new
  `describe` blocks: wrapped items open rich and save byte for byte, and the
  guards on what is still not forgiven
- .tasks/review/LAI-853-rich-editor-refuses-a-wrapped-list-item.md — Result,
  Evidence
- .tasks/backlog/LAI-302-rich-editor-wrapped-task-list-item.md — filed

**Decisions**
- Forgive indentation only on a line under paragraph text that starts no block,
  rather than all leading white space — `1. a\n  - b` parses the same in TipTap
  either way but react-markdown renders two lists, so forgiving it would open
  a document the editor shows differently from the board.
- Normalise the parsed text rather than teach the writer to indent — the lexer
  left one stray space under `1. `, which is a parse error, not a layout one,
  and an untouched block is copied from the source anyway.
- The wrapped task-list item stays Markdown — TipTap reads its second line as a
  code block or a second paragraph; fixing that is replacing a library
  tokenizer, not a bridge change.

**Discovered**
- `@tiptap/extension-list` 3.32.0's task-list tokenizer takes only an item's
  first line as its text → LAI-302 filed (discovered-from: LAI-853).
- `pnpm install` in a fresh worktree needed nothing else; the worktree had no
  `node_modules` at all.
