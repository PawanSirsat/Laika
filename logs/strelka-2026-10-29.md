- cli/src/agent-session.ts — `readSelfReport` reads the harness's version and
  model from the hook input and the harness's own transcript (bounded, regular
  files only); the start sends `harness` always and `harness_version` /
  `model` only when read; a heartbeat sends only what changed since the board

  tells `released` / `transferred` not to reclaim

  the start, and notes it on every non-end hook for the watcher's next beat

  bodies, omission, resend after a lost beat, key-bound retry body, transcript

  harness, version and model, and a mid-session model switch reaching it
- cli/README.md — what the session reports, and released vs expired

**Decisions**
- Version and model come from what the harness itself wrote (hook input,
  transcript) — rejected running `claude --version` / `codex --version`:
  with the helper's fixed PATH it may find a different binary from the one
  running, which would be a guess.

  the body with the key and answers a mismatch `409`, so a body that grew
  between attempts would have stranded the start.

## 2026-10-29T10:23:07Z — LAI-588 (Codex review, two blocking)

**What changed**
- cli/src/agent-session.ts — `beatOnce` marks fields `reported` only on a
  `200` (any 2xx did before, against its own comment); `transcriptEnds`
  opens with `O_RDONLY | O_NONBLOCK`, then `fstat`s the descriptor (it
  stat'ed the path, then opened it: a FIFO swapped in between could block the
  hook); exported, with `open` injectable so a test can swap at the open
- cli/test/agent-session.test.ts — a 201 heartbeat leaves the model to be
  resent; a FIFO swapped in at open, and a plain FIFO, both refused in a child
  process under a 10 s timeout

**Decisions**
- No `O_NOFOLLOW`: a symlink to a regular file was read before and the
  README promises only "a regular file", so the behaviour is kept.
- The old in-process FIFO case moved into the child: with blocking open it
  hung the whole suite rather than failing — found when the O_NONBLOCK
  mutation timed out the harness.

**Discovered**
- The descriptor's `isFile()` check survives its mutation: a FIFO or device
  reports size 0 and is refused by `size <= 0`, and anything else fails the
  positional read and is caught. It is defence in depth, not tested.
