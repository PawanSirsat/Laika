## 2026-11-02T01:30:00Z — LAI-1062

The compatibility manifest said every V3 feature was off while device pairing
(LAI-1050, #205) and the tool setup exchange and client reports (LAI-1056,
#211) were serving. Built by a polly-dispatched builder on Belka: worktree
`.polly/wt-1062`, branch `LAI-1062-compat-features-on`, card LAIKA-916.

**What changed**
- `server/src/services/developer-compat.ts`: `FEATURE_ROUTES` names each
  feature's routes as `METHOD path`; `servedFeatures()` turns a feature on
  exactly when every one is mounted, and an empty list never is.
  `project_setups` has none, since there is no server-side record, so it stays
  `false`. `PROTOCOL` is `{ current: 2, minClient: 1 }`, and `WHATS_NEW` has a
  protocol-2 line.
- `server/src/http/routes/developer.ts`: the body is built on the first
  request, from a `servedRoutes()` thunk, because the router is mounted before
  the routes it reports on.
- `server/src/app.ts`: passes `app.routes` as `METHOD path`.
- `docs/SPEC.md` §6.4: a named edit (D-033) to the compatibility paragraph.
- Tests: `server/test/services/developer-compat.test.ts` (10) and
  `server/test/http/routes/developer.test.ts` (12).

**Decisions**
- **Derived, not declared.** A flag written as `true` beside the routes would
  rot the same way `false` did. Reading the route table means an app without a
  database (`testApp()`) honestly reports all four off.
- **Protocol 2, min_client 1.** This follows the plan (§E.6 sample
  `whats_new: [{ protocol: 2 }]`) and `min_protocol_for: 2`. A protocol-1
  helper is still accepted and is told only which features it is missing.

**Discovered**

  after #213, so `laika doctor` on a current checkout says *"Update required
  for device_pairing, tool_setup_exchange, client_reports"*. That is §4.4's
  two-owner shape. LAI-1064 also carries this task's second criterion, the
  `device.ts` manifest gate.
- The route-table test cannot see a *removed* route: removing one flips its
  flag off and the loop skips it. I measured this by unmounting
  `/tool-setup` (anchor confirmed). The pinned-flags test and the 404 test went
