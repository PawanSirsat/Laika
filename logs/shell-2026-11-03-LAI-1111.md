**Decisions**
- The `script` fallback runs on Linux instead of skipping: CI's Ubuntu image
  has no `expect`, and a skipped pty test would leave CI with only the
  PassThrough tests. macOS's `script` cannot be the fallback: it refuses an
  input that is not a terminal (`tcgetattr/ioctl: Operation not supported on
  socket`).
- Harness questions (Codex's `danger-full-access`, Omnigent's two) now come
  before the project questions, with the checks. The order of answers changed
  for anyone scripting `enable`.
- No terminal at all still says "needs a terminal"; only input that ends on a
  terminal says "input ended". `ServiceIo.terminal` tells them apart.
- `--dry-run` validates by writing the config to a `mkdtemp` scratch home and
  calling `loadConfig` on it, then removing it: `agent-launcher.ts` is the
  parallel builder's file and `loadConfig` reads only from a home.
- The MCP hint names the screen as it is: Developer access → Tools → the tool
  → *Reconnect (new credential)…*. The dispatch said "⋯ → Reconnect"; that
  panel has no ⋯ menu.
- `git symbolic-ref --short -q HEAD` names the branch: `rev-parse
  --abbrev-ref` fails on an unborn branch.
