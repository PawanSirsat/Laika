**What changed**
- cli/src/agent-launcher.ts:
  - **Locks.** `acquireLock` creates a lock file whole (temp file plus
    `link`). A dead holder, judged by pid and start time, is cleared under a
    break lock named for that holder; the lock is re-read under it and removed
    only if it still names that holder. A dead breaker is cleared the same way,
    up to three levels. The age rule and `STALE_LOCK_MS` are gone.
  - **Leftovers.** `reapLeftovers(…, pastDeadlineOnly)` ends leftovers;
    `status` uses it, under the lock, to end leftovers past their deadline.
    `stop` takes the lock before reaping. Only records known to be dead are
    cleared; unknown ones are kept, never signalled, and shown by `status`.
  - **argv[0].** Must be owned by you or root; neither its folder nor its
    symlink target's folder may be group- or other-writable.
  - **Agent id.** `judge` returns `agent_unknown` for an unknown agent id; the
    loop resolves it with `deps.addressee` (the offer's `to_agent_id` in this
    credential's inbox) or refuses with `agent_unresolved`.

  cli/test/support/launcher-run-child.ts: adds `addressee`.
- cli/README.md: the lock, leftover, argv[0] and agent paragraphs.

**Decisions**
- The break lock is keyed **per dead holder** rather than being a single
  `.reap` file. A single file judged by liveness still lets two contenders who
  both saw it dead each remove the other's fresh one. A lock named for one
  dead holder can only ever be broken once.
- An unreadable lock now refuses rather than ageing out. Launchers write
  whole, so unreadable means someone else wrote it, and the message says to
  remove it.
- `status` now ends leftovers past their deadline (the review asked for this),
  and takes the lock to do it; otherwise it only reports.
