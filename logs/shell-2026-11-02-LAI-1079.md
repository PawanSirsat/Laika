**Decisions**
- *Connected* means the Devices tab's every status but *Needs setup*
  (`toolStatus`), not just `last_seen_at !== null` — so an expired credential is
  *needs setup* here as there. Rejected the old Overview's rule because the
  numbers must agree with Devices.
- "Finish connecting" only when **no** tool is connected; once one is, the hero
  moves to project setup and the rest go in the attention note. One next step,
  never two.
- A setup row is one tool × one project (records grouped), its chip
  `setupEvidence`'s verdict: *Checked* only with a current local check;
  self-report alone *Recorded by you* with "not verified" in the line; a check
  that found no block is listed but not counted as set up. A disconnected
  tool's records are left out (counts exclude revoked).
- The setups read failing is its own error state with retry, not an empty list
  — an empty list would say "Set up your project repository" on a read that
  never arrived.
- Helper updates: read `/developer/compatibility` + each seen tool's
  `/verification` directly with `update-status.ts`'s pure functions rather than
  mounting `UpdatesProvider`, which LAI-1080 is reshaping.
