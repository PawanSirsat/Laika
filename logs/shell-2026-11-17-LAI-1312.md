- Hiding: `requires: 'meeting.read_own'` plus a composed holder that also needs the
  list's `enabled`, read once per page load with `limit=1` — and only when
  `/setup/status` says `sign_in: microsoft`, so a password instance never asks and no

  `/developer/compatibility` (a server change, CORE's), and `/org/sso` (members are
  refused it). Same shape as Insights' `insightsHolder`.

  week's meetings would otherwise vanish from the page.

  without a request; otherwise it asks only when mounted. A mutation that mounted it
  eagerly turned the browser test red (checked, then restored).
- Owner's sync-off state lists the Graph permissions from `/org/sso`'s
  `meetings_sync.permissions`, not a hard-coded list.
