## Goal

My day's lane timeline (the owner's "Laika App v2" design, LAI-831) has an
AGENTS lane: when Claude Code worked for the person, as blocks along the
hours, grey when not tied to a card. LAI-831 left it out because nothing
serves it.

## Found (LAI-831's census)

`agent_time_days` (§4.50) holds **seconds per (person, day, session, kind)**
from Claude Code's `active_time` metric. It has no time of day, so My day can
total agent minutes per card (the right column) but cannot place them on the
day. Drawing them anywhere would be inventing a time (§5.1, D-032).

## Acceptance criteria

- [x] The server keeps when agent time happened, at a resolution that tells
      nothing about content (for example, minutes active per 15-minute bucket
      per session), from what the OpenTelemetry receiver already receives.
- [x] `GET /me/time` serves it for the day, the person's own, session only,
      tied to a card the way agent minutes are.
- [x] My day draws the AGENTS lane from it, grey for time on no card.
- [x] Tests fail on today's code; the gate exits 0.

## Notes

Agent time stays minutes beside the day, never hours in it (D-088 item 8).

- **When, kept by the receiver** (`server/src/services/token-telemetry.ts`,
  `agent-time.ts`). Each `active_time` point of `type=cli`, the agent
  working, adds its seconds to the buckets its interval covers, in
  proportion (`spreadActive`). The interval is a delta point's own, or a
  cumulative series' growth since its last point. Seconds past the
  interval's length (active time past wall time, which only a bad point can
  say) go in the stretch that long before its end, so no bucket holds more
  than five minutes. `storeAgentBuckets` upserts with `min(300, …)`, so two
  series of one session over the same minutes can never trip the CHECK and
  fail the upload. The keyboard (`type=user`) is not bucketed.
- **The table** `agent_time_buckets` (`user_id`, `session_key`, `bucket` =
  `floor(ms / 300000)`, `seconds` 0–300, `updated_at`). Its primary key is
  `(user_id, session_key, bucket)` and its index `(user_id, bucket)`.
  Migration `0046_agent_time_buckets.sql`, generated by
  `pnpm --filter @laika/server run db:generate --name agent_time_buckets`.
  It is dropped with a session the collector leaves out (`dropAgentTime`),
  deleted with the person's history (`deleteOwnLocalActivity`), and kept 40
  days (`pruneLocalActivity`, by `SESSION_DAYS_KEPT`). The totals in
  `agent_time_days` keep their 400 days.
- **Served:** `GET /me/time`'s `agent.lane`, per five minutes, `[bucket start
  in unix ms, seconds, seconds on a card]`, for the day in the zone My day
  reads it in. A bucket is on a card when its session's own split
  (`token_session_tasks`) ties it, the same rule as the agent minutes per
  card. It is one indexed range of buckets, the UTC day widened fourteen
  hours each side, each bucket kept where its start falls (`dayIn`). The
  person's own, on a web session, inside My day.
- **My day** (`timeline-derive.ts`, `Timeline.tsx`, `my-day.css`).
  - `dayLine` joins back-to-back buckets into one bar while they stay on a
    card or off one. A bucket is on a card when most of its time is. Bars
    widen the axis as blocks do, and a bucket not on the day is left out.
  - An AGENTS row is drawn under the blocks only on a day that has one:
    blue (`--chip-blue-*`) on a card, grey (`--chip-neutral-*`) on none. Each
    bar is titled *"Agent working 9:00–9:10 AM · 9 min"*, plus *"· on no
    card"* when grey.
  - The legend gains *Agent working*, and *Agent, no card* when one is grey.
  - The label column is now one flex column, each label as tall as its row.
    That replaces LAI-834's padding arithmetic, and holds for Signals, You
    and Agents in any combination.
- **SPEC** §4.57 `agent_time_buckets` (fields, keys, the spreading, the

  LAI-836, which rewrites it. LAI-836's §4.55–§4.56 will meet this §4.57 at
