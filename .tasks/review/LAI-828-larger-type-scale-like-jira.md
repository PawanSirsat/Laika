## Goal

Text across Laika is as easy to read as Jira's. Owner, 2026-10-21:

> *"the text size is also very small, we need to increase it everywhere …
> find where the text size is small all over the web app and increase that; I
> want the same as the Jira board"*

Today `server/web/src/styles/type.css` sets body text at 13px
(0.8125rem) and many labels at 9.5–12px (0.59375–0.75rem).

Made on the owner's direct instruction.

## Target scale (Atlassian Design System's published sizes, which Jira uses)

| Role | Size / line-height |
|---|---|
| Body (default UI text, table cells, card titles, form fields) | 14px / 20px |
| Reading text (description, acceptance, comments, docs-like content) | 16px / 24px |
| Small (secondary lines, meta, timestamps, chips) | 12px / 16px |
| Smallest allowed (tiny badges, counters) | 11px, and only where 12px truly cannot fit |
| Headings | page title 24px / 28px; section 20px / 24px; card/panel heading 16px / 20px |
| Task panel title | 24px / 28px |

## Work notes (LAI-828, owner-direct)

### The scale, as built

Seven steps, declared once in `TYPE_SCALE`
(`server/web/src/theme/type-roles.ts`) and generated by
`scripts/generate-type-css.ts` into the `:root` block at the top of
`server/web/src/styles/type.css`:

| Step | Size / line-height | Tokens | Role |
|---|---|---|---|
| `tiny` | 11px / 16px | `--text-tiny`, `--leading-tiny` | the named badges and counters only |
| `small` | 12px / 16px | `--text-small`, `--leading-small` | secondary lines, meta, timestamps, chips, keys, field labels, uppercase section labels |
| `body` | 14px / 20px | `--text-body`, `--leading-body` | default UI text, table cells, card titles, form fields, buttons |
| `reading` | 16px / 24px | `--text-reading`, `--leading-reading` | description, acceptance, comments |
| `heading-sm` | 16px / 20px | `--text-heading-sm`, `--leading-heading-sm` | card or panel heading |
| `heading-md` | 20px / 24px | `--text-heading-md`, `--leading-heading-md` | section heading, dialog title |
| `heading-lg` | 24px / 28px | `--text-heading-lg`, `--leading-heading-lg` | page title, task panel title |

- **Where the tokens live.** The criterion names `styles/type.css`; before this
  task the type tokens were in `styles/theme.css` (`--text-xs` … `--text-xl`)
  and `type.css` held only the roles. They moved: `type.css` now carries the
  scale and the roles, both generated, and `theme.css` keeps colour, weight,
  radius and spacing. `token-list.ts` derives `TYPE_TOKENS` from the scale;
  `tokens.test.ts` stops looking for them in `theme.css`; `type-roles.test.ts`
  asserts the `:root` block value by value against stated numbers, not against
  the object alone.
- **Roles name a step**, not a pixel size (`step: 'body'`), so a role cannot be
  off the scale. Single-line roles keep `line-height: 1` (a chip or control is
  sized by its padding); text that wraps takes the step's leading.
- **Density** keeps every size: the dense board only tightens the card title's
  leading to 1.3. Its old 10.5px meta and labels were under the floor and would
  now equal the default.
- **`type-floor.test.ts` is the guard**, rewritten for this scale: every size —
  `font-size`, or the size in a `font` shorthand, with or without the `;` a
  block's last declaration may omit (round 2) — is `var(--text-<step>)` or `0`;
  nothing resolves under 12px but `--text-tiny` on the named list; the named
  list and the selectors using `--text-tiny` are equal, both directions; the rem
  anchor (`index.css` `:root { font-size: 16px }`) is the one raw size and the
  one exemption. LAI-706's avatar exemption is retired — avatar initials are on
  the tiny list instead.
- **`type-css-drift.test.ts`** (round 2) renders `type.css` with the generator's
  own code (`scripts/type-css.ts`) and compares it byte for byte, which covers
  the density block and comments `type-roles.test.ts` does not read.
- **No legacy names, no My day exemption** (round 2). Until My day v2 (LAI-831)
  landed, `--text-xs` … `--text-xl` survived as aliases for My day only, held by
  an exemption whose last test was written to fail once My day needed neither.
  After the merge and My day's sweep it did — *"My day is on the scale: retire
  its exemption"* — and the aliases, the exemption, its 10px floor and the
  legacy-name test were deleted. A retired name put back in `my-day.css` is red
  in the floor test and in `tokens.test.ts`.
